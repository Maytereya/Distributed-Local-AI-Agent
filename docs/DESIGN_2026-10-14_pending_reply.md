# «Ответ на висящий вопрос бота» силами LLM — консенсус сессий (14.10.2026)

Источник: аудит облачной сессии 14.10 (`docs/HANDOFF_2026-10-14_cloud_L14.md` в `wip`, «Правила, привязанные к
конкретной формулировке»), ответы сессий «Рефактор choose() модуля» и «МЕГА СЕССИЯ БОТА ultracode». Решение — владельца.

## Проблема

Все «да/нет» на вопрос бота решают правила без LLM: `recovery_policy.contextual_reply_kind` (`recovery_policy.py:72`) →
`policies.is_context_affirmative/negative` → `_is_affirmative_text`/`_is_negative_text` (`policies.py` ~2506–2640);
подтверждение записи — отдельно `policies.appointment_confirmation_transition` («да» — только если каждое слово из
`_CONFIRM_YES_WORDS`). Не понимаются «нет, спасибо», «да, отмените», «конечно, переведите», «наркоз не нужен» (→ «с
наркозом»); петли без счётчика в подтверждении/отмене записи. 11 мест вызова: `router._handle_appointment_action_pending`
:708, `_handle_prepare_variant_pending`:773 (наркоз), `_handle_compound_price_pending`:831,
`_handle_catalog_confirm_pending`:978, `_handle_secondary_queue_pending`:2418, `_handle_operator_offer_pending`:2467;
`orchestrator._extract_pending_response`:254; `appointment_flow_guard.should_keep_appointment_flow_override`:122,
`is_new_topic_while_confirm_pending`:142, `run_appointment_precheck`:228/286.

планом: (а) правила → (б) кнопки (нужен шлюз) → **(в) узкий LLM-валидатор «согласие / нет» с fail-closed в переспрос —

## Порядок (обе сессии)

1. Влить облачную ветку (L-14 шаги 2–4) и **замерить `context_shown`** (вечерний dev + двухходовой набор стенда) —
   новый клиент читает «что показано и что спрошено», без стабильного `context_shown` он «на песке».
2. Затем `pending_reply` — **сначала тень** (`choose(..., shadow=True)`, вне бюджета), согласие с правилами на трафике,
   **выключатель на каждый тип вопроса**, потом `on`.

## Дизайн (сведено)

- **Поле ожидания** (принцип 5): `state.last_entities["_expects"] = {"kind": "yes_no"|"pick", "question": <текст
  вопроса бота>, "options": [...], "asks": n}` — пишется там, где бот задаёт вопрос (`mark_operator_offer_pending`,
  `_catalog_confirm_*`, `appointment_flow_guard`, compound price pending); сейчас текста вопроса в состоянии нет.
  В промпт — вопрос бота в данных хода (роль user, через `_clean_question`: в вопросе бывают слова пациента), без истории;
  без ПДн (кэш и журналы).
- **Задача:** `Task(name="pending_reply", max_picks=1, outcomes=("yes","no","pause","new_topic"), timeout_s=8,
  queue_timeout_ms=3000)`; пункты — только список, показанный ботом; пусто/`none` → NONE_FIT → обычный NLU.
- **Ловушка модуля:** в `choice._judge` исход побеждает выбор и теряет номера («да, второй») — правка `_judge` с тестом
  класса, не трогая срочность; либо в вопросах-списках без yes/no.
- **Быстрый путь без LLM:** вся реплика — один голый якорь («да», «нет», «ок») → `is_context_affirmative/negative`
  (−1–3 с и слот ollama на самом частом ответе). Регэкспы не удалять — запасной путь; снимать по храповику после замера.
- **Составные ответы** («нет, мне ферритин», «да, и ещё…») — остаток в NLU, не терять.
- **Несколько висящих вопросов** (вторичная очередь + оффер) — на какой ответ, решает код.
- **Бюджет:** «да, и сколько стоят оак и ферритин» = pending_reply + turn_parse + корзина = 3 > 2 → pending_reply
  первым; если исход ≠ new_topic/none — ход закрыт; иначе лимит 3 (10 с оставить), исход `budget` в телеметрии.
- **Сбой LLM:** правила + **предел переспросов в коде** (`_expects.asks`; инвариант 3bacf58 «шаг дважды без
  продвижения → назвать недостающее или оператор»), не «сразу оператор» (лавина переводов).
- **«Пауза»** («я подумаю») — решить: снять ожидание без оффера или держать по TTL pending — иначе новая петля.
- **Телеметрия:** исход (yes/no/pause/new_topic), счётчик переспросов.

## Асимметрия безопасности по типу вопроса (МЕГА)

| Вопрос | Правило |
|---|---|
| Срочное | precheck первым, до разбора висящего вопроса (`router.py` ~3194, `f0c6165`); «нет, мне плохо» не становится «нет» на оффер |
| Подтверждение записи | LLM может только **понизить** «да» до переспроса, не превратить «другое» в «да»; сбой → переспрос; инъекция — `tests/test_appointment_confirm_refusal.py` |
| Отмена существующей записи | всегда оператор (25.09; BUG-2026-10-07-CANCEL-LOW-CONF-CLARIFY открыт); «нет»/«пауза» от LLM не глушит глагол отмены с объектом |
| «Отменить текущий процесс записи?» | ложное «да» стирает собранное; явное «не отменяйте» по правилам перекрывает LLM |
| Оффер оператора | «да» от правил ИЛИ LLM → перевод (безопасное направление); ложное «нет» опасно |
| «Вы имели в виду X?» | ложное «да» = чужая цена → при сомнении список/переспрос |

Проверить: нигде «да» не исполняет необратимое действие напрямую (решения 04.10/08.10 — через оператора).

## Зависимости (МЕГА)

Кнопки: `button_id` сбрасывает висящий вопрос раньше всех (`router.py:3187`) — новый вызов после сброса. Шлюз реагирует на
`handoff=True` — меняется частота переводов (правило ≤3). FreeTalk `contextual_reply_kind` не импортирует (свои регэкспы
`signal_parsers.py:86-88`, `interrupt_policy.py:102` — находка Владимиру, не трогать). Гейт герметичен (LLM заглушена) →
нужен свип через эндпоинт с прод-LLM и стенд; **встречный свип: 32 из 40 типичных ответов (`69d257b`) не меняются**.
Внутри записи меняется свойство «в записи LLM не зовётся» (`flow_policy.prelock_active_appointment_turn`).

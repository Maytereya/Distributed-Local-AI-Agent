# Дизайн: «одна позиция или семейство» — отдельный вопрос LLM перед выбором строки цены (вариант В, 30.10 вечер)

Штурман-наследник, по слову владельца «Дизайн варианта В» (30.10, 19:00 Самара / 22:00 у владельца). Код — выключатель `price_scope_llm` (off), запись журнала BUG-2026-10-31-PRICE-FAMILY-ONE-ROW. Связано:
STEP-2026-10-30-STEP5-3B-PRICE-SELECT (5.3б не прошёл дважды), карта провалов кнопок M2 «цена семейства» (48 из 208),
решение владельца 22.07 («при неоднозначности — список, а не одна цена»), BUG-2026-10-20-BRANCH-SIDE-PRICE-ONE-ROW,
BUG-2026-09-30-SURGEON-PRICE-FOR-SPECIALIST (инвариант «вариантов несколько — список»), память «вердикт — отдельный вопрос LLM».

## 0. Итог

- **Класс.** Пациент назвал услугу, у которой в прайсе несколько вариантов с разной ценой, и не сказал, какой
  («Уролог цена приёма», «Биохимический анализ крови», «хламидиоз»). Бот показывает одну строку. Цена может быть
  не той, что ждёт пациент. Это прямо против решения 22.07.
- **Масштаб.** Стенд кнопок, деплой 23 — 26 провалов «одна цена вместо списка». **21 из 26 — выбор LLM** (`price_policy = picked`).
  По разметке: 16 `family`, 9 `single` с пометкой `ambiguous`, 1 `multi`. 9 «single» — спорная разметка: «Хгч» → общий ХГЧ, там
  одна строка скорее верна. Разметка LLM v1, не проверена (`verified: false`).
- **Корень — не «LLM вместо правил», а четыре слоя, и каждый сужает до одной строки:**
  1. промпт `choose_price_service_*`: «ИМЕННО та услуга» и правило 4 («особый вариант — к.м.н., повторный, детский, на дому,
     cito — не выбирай, если есть без него»);
  2. код `_prefer_base_variants` (`_HARD_VARIANT_FLAGS`: cito, capillary, child, home, repeat, kmn) — флаги по буквам названия;
     после выбора LLM отбрасывает варианты ещё раз;
  3. у цены приёма врача рендер `doctor_consult` берёт первую строку розницы (`retail_prices[0]`,
     BUG-2026-10-20-BRANCH-SIDE-PRICE-ONE-ROW — там починено только для побочного вопроса в записи);
  4. 5.3б отдал выбору LLM и ходы, где название подставлено по буквам, и дефект слоёв 1–2 проявился там:
     «ОАК» — список → «похожие», «респираторная панель» — список → одна строка.
- **Решение.** Разделить два вопроса, которые сейчас решаются одним вызовом:
  - «что просит пациент» — одна позиция / семейство / слишком общее;
  - «какие строки».

  Вопрос «что просит» — короткий, закрытый, отдельный. Для «семейства» выбор строк идёт в режиме «все варианты этой услуги,
  кроме чужих» (LLM — фильтр, не выборщик). Слои 2–3 для семейства не действуют. Правила остаются сборщиками кандидатов.
- **Цена в задержке.** Вопрос задаётся только при конфликте: LLM выбрала одну строку, а кандидатов той же услуги ≥ 2
  (правила показали бы список). Оценка — короткий вызов ≈ 1–1,7 с только на таких ходах. Число таких ходов — первым делом
  в режиме shadow.

## 1. Где решается класс сейчас (цепочка)

Цепочка хода «сколько стоит X» (`planner` PRICE → `prices.price_info` → `_price_select_llm.select_price_rows` → рендер):

| Слой | Что делает с семейством | Буквы или смысл |
|---|---|---|
| поиск кандидатов правил (`_build_pool`, синонимы МИС, редкие слова) | находит все строки семейства (до 24 в пуле) | буквы — **оставить** (сужает кандидатов для LLM) |
| сильное совпадение (`_strong_by_parse`) | дословное название / синоним / код — без LLM | данные — оставить |
| выбор LLM (`choose_price_service_*`) | «ИМЕННО та» + правило 4 → чаще одна строка | смысл, но вопрос задан неверно для семейства |
| `_prefer_base_variants` | убирает к.м.н., повторный, детский, на дому, cito | **буквы после смысла** — для семейства снять |
| `_checked` / `settle` / политика `rules_list` | список правил — только при сбое LLM | — |
| рендер `doctor_consult` | первая строка розницы | код — для семейства список |

## 2. Новый механизм

### 2.1 Вопрос «что просит пациент» (`choose_price_scope`)

- **Вход** (роль user после `<<DATA>>`): фраза услуги из разбора хода (`turn_spans`, иначе реплика), вопрос бота, если был,
  и названия кандидатов-строк без цен (≤ 12, порядок пула).
- **Схема:** `{"scope": "one" | "family" | "general", "named_variant": bool}`.
  - `one` — пациент назвал конкретную позицию или признак, который её выделяет («к.м.н.», «первичный», «с эластографией»,
    «общий ХГЧ»);
  - `family` — назвал услугу, у которой в списке несколько вариантов, и не сказал, какой;
  - `general` — слишком общее («анализы», «приём врача» без специальности; то же, что `too_general` сейчас).
- **Когда зовётся.** Первый выбор вернул ровно одну строку, и среди кандидатов ≥ 2 строки, которые правила показали бы
  (`shown`), или выбор с промптом семейства (2.2) найдёт ≥ 2. Иначе вопроса нет — нет и задержки.
- **Почему отдельно, а не полем в выборе:** проверка внутри вызова выбора защищает сам выбор (ДМС 15/15 мимо суда, `partly`
  4/5 ложно — память «вердикт — отдельный вопрос»).
- **Почему не в гибрид шага 4:** там вызов не видит прайса, а «семейство» — факт о прайсе («ОАК» — семейство, потому что строк
  несколько). Поле `has_service` шага 4 остаётся; можно добавить подсказку «назван признак варианта», но решение — здесь.

### 2.2 Строки для семейства (`choose_price_service_family`)

- Тот же модуль `choose()` и тот же пул; промпт — копия `*_qualifier_general` с другими правилами 4 и 5.
  Правило 5: «выбери ВСЕ варианты этой услуги». Правило 4 — по ответу владельца (вопрос В1, §5).
  Правила 1–3 без изменений: смысл, уточнения, условие «по ОМС» → ни одной.
- Выход ≥ 2 строк → `PriceSelection(rows=…, status="family")`: рендер списка «нашёл варианты стоимости»
  (уже есть). `_prefer_base_variants` для `family` не применяется (или только по ответу В1).
- Выход ≤ 1 → остаётся первый выбор: дефект не углубляется.
- Длина списка: потолок N строк (предложение: 8), базовый вариант первым, остальные — «и ещё K вариантов, уточните» (В3).

### 2.3 Рендер цены приёма врача

`doctor_consult` при `status == "family"` печатает список строк (как `format_consult_price_rows` из
BUG-2026-10-20), а не первую строку. Врачи — как сейчас.

### 2.4 Связь с 5.3б

Читатель `price_select` остаётся выключенным. После карточки В — перемер 5.3б при включённом В: класс «буквенный список →
одна строка» должен закрыться на уровне выбора, тогда 5.3б перестаёт его вскрывать.

## 3. Выключатель, телеметрия, промпты

- `[MESSENGER_ROUTER] price_scope_llm = off | shadow | on`, по умолчанию `off` («как было»).
  - `shadow`: вопрос 2.1 задаётся, ответ пишется в журнал, ответ пациенту прежний — даёт число ходов-конфликтов и задержку на проде.
  - `on`: действует.
- Телеметрия хода: `price_scope` (`one` / `family` / `general` / `skip` / `unavailable`), `price_scope_ms`, `price_family_rows` (число строк).
- Промпты в двух локациях: `messengers_router/prompts/choose_price_scope.txt` = `app_data/prompts/mr_choose_price_scope.txt`,
  `choose_price_service_family.txt` = `mr_choose_price_service_family.txt`.
- Отказ LLM в вопросе 2.1 → как сейчас (первый выбор). Лимит решений хода (`budget`) → как сейчас.
- Храповик правил: `_HARD_VARIANT_FLAGS` перестаёт решать для семейства. Счётчик не растёт, новых регэкспов и словарей нет.

## 4. Инвариант класса, покрытие, критерии

- **Инвариант `price_family_shows_variants`:** пациент назвал услугу, у которой в прайсе ≥ 2 варианта с разной ценой, и не назвал
  признак варианта → в ответе все варианты этой услуги (до потолка, со ссылкой на остальные) и ни одной строки другой услуги.
  Назвал признак → одна строка. Слишком общее → уточнение без цен.
- **Тест на класс** `tests/test_price_family_scope_class.py`: через `messenger_generate_once`, подделка LLM настоящего типа
  (`choose()`), прайс ≥ 100 строк.
  - Матрица: приём специалиста (уролог, ЛОР, невролог) × без признака / «к.м.н.» / «первичный»; анализ-семейство (биохимия,
    хламидиоз) × без метода / «ПЦР»; одна строка (ферритин) — не меняется.
- **Карточка** (критерии объявить до живого прогона): кнопки, test, dev — `on` против `d23on_*`.
  - «одна цена вместо списка» кнопок 27 → ≤ 15;
  - чужая цена не растёт ни в одном наборе (6 / 1 / 5);
  - «список с нужной» не падает;
  - переводов и уточнений не больше, правило ≤ 3;
  - длиннее 1 500 знаков — не больше +10;
  - p95 ценового хода — не больше +2 с.
- **Встречный свип по живому прайсу (офлайн, срезы закреплены):**
  - все приёмы специальностей (28) и топ-50 анализов, у которых ≥ 2 строки, — в списке нет чужих строк;
  - 50 одиночных услуг — ответ не изменился;
  - отдельно — синонимы МИС с одной строкой: не превратились в список.
- **Разметка:** 26 провалов M2 перепроверить вслепую до замера (скептик, без вида ответов бота): 9 «single + ambiguous» спорны.
  Не подгонять промпт под разметку (память «Гудхарт»): dev — для замысла, test — для вердикта.

## 5. Вопросы владельцу — решены 30.10: по рекомендации (В1 (а) да / (б) нет; В2 карточка на стенде; В3 — 8 строк)

- **В1. Особые варианты в списке семейства.** Если пациент не назвал признак, показывать ли:
  - (а) варианты врача — к.м.н., первичный / повторный, категория, конкретный врач. Рекомендую — **да**:
    это вопрос «какой», и 22.07 / BUG-2026-10-20 уже показывают все строки приёма;
  - (б) варианты условия — cito, на дому, капиллярная кровь, выезд. Рекомендую — **нет, пока пациент не попросил**:
    это доплата, которую он не просил (правило 4 для них остаётся).
- **В2. Порядок внедрения:** shadow на проде (неделя, число конфликтов и задержка) → карточка → on. Либо сразу карточка на стенде
  без shadow. Рекомендую карточку на стенде, shadow — вместе с ближайшим деплоем.
- **В3. Потолок списка:** 8 строк, остальные — «и ещё K вариантов, уточните». У ЛОР 13 строк приёма, у невролога 9.

## 6. Риски

- Длинные списки (ЛОР 13 строк) — потолок В3; ответ длиннее.
- LLM назовёт «семейством» то, где пациент выделил вариант словом, которого нет в названии («обычный ХГЧ»). Лишняя строка в
  списке — безвредная ошибка; критерий «чужая цена не растёт» её ловит, если строка чужая.
- Рост задержки на ценовых ходах с конфликтом — меряем в shadow.
- Разметка не проверена — см. §4.

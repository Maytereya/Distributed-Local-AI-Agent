# Принципы архитектуры бота — «конституция проекта»

Принято владельцем 2026-10-08 (повестка большого рефакторинга, вопрос 2). Каждое архитектурное решение
и каждый фикс ссылается на пункт, которому соответствует. Решение, нарушающее пункт, не принимается
без явного решения владельца, записанного здесь в «Исключениях».

**Регистратура как образ.** Справочник печатает цены и адреса. Администратор понимает вопрос и
показывает пальцем строку справочника, а не пересказывает по памяти. Нет строки — зовёт старшего.
Тревогу поднять может любой, снять — никто. Администратор всегда знает, какой вопрос он задал и
какого ответа ждёт.

## Пять пунктов

| # | Принцип | English | Что запрещено |
|---|---|---|---|
| 1 | **Факты печатает код из данных МИС**: цену, адрес, ФИО врача, дату, время, срок готовности, телефон. LLM пациенту чисел и фактов своим текстом **не пишет** | single source of truth; LLM never authors facts | цифры, названия, адреса и ФИО, сгенерированные LLM; заглушки вида «[номер телефона]» в ответе |
| 2 | **Смысл слов пациента понимает LLM — выбирая номер из найденного.** Правила и поиск собирают кандидатов, LLM возвращает номер, метку или «ничего не подходит». Сомнение → список вариантов, а не одна, возможно чужая, позиция | closed-set selection: rules propose, LLM disposes | окончательный вердикт по совпадению букв или ключевому слову (услуга, врач, намерение) |
| 3 | **Нет данных → честное «уточню у оператора»** с настоящим переводом (или с честным сроком, когда операторов нет) | abstention, graceful degradation | свободный текст на пустых данных; «у нас этого нет» без поиска по данным; «уточните у оператора» без перевода |
| 4 | **Безопасность монотонна**: любой слой может поднять срочность, ни один — снять | monotonic safety | снятие метки срочного правилом, LLM или пост-обработкой |
| 5 | **Бот всегда знает, чего ждёт, и не ходит по кругу.** Ожидаемый ответ задан явно (дата, ФИО, да/нет, выбор из списка). Ответ, не подходящий под ожидание, не втискивается в графу. Шаг дважды без продвижения → назвать, чего не хватает, или оператор | explicit dialog state; no-progress invariant | любая фраза в графе ФИО или даты; третье подряд «Уточните детали»; отказ, понятый как согласие или перенос |

## Как применять

- **В фиксе** — в записи журнала багов (`docs/messengers_router_bug_log.md`) указывать пункт: «инвариант
  класса следует из пункта N».
- **В ревью** — первым делом спросить: какой пункт затронут и не нарушен ли соседний.
- **Проверка, а не лозунг.** У каждого пункта со временем появится проверка: архитектурный тест или
  метрика эталонного набора. Например, для пункта 1 — «каждое число в ответе есть в данных хода»;
  для пункта 5 — «ни один шаг не повторяется трижды подряд».

## Решения, которые из этого следуют

- LLM не пишет пациенту чисел своим текстом (закрыто 08.10).
- Существующую запись пациента бот не ищет и не показывает: ФИО — не удостоверение личности; поиск
  записи — оператор (08.10; журнал BUG-2026-10-08-EXISTING-APPT-LOOKUP-MISSED).
- Дезинформация ценой строго хуже уточнения (22.07) — частный случай пунктов 2 и 3.
- Синонимы услуг и знания о клинике — данные МИС, не списки в коде — частный случай пункта 1.

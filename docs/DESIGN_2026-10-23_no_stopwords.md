## 2. Этап 1 — разбор реплики без списков (выключатель `turn_spans_llm`, off)

Сейчас: фразы-кандидаты — реплика без обвязки (W), фрагменты по разделителям, окна сегментации корзины, сильные окна, варианты;
«обвязка» и «родовые слова» — три списка цены. LLM выбирает только среди этих окон.

Станет (принцип 2: LLM выбирает номер из перечисленного; строки — данные МИС):
- **LLM размечает слова реплики.** Реплика показывается с номерами слов (токены `_PRICE_TOKEN_RE` — механика):
  «1:Сколько 2:стоит 3:анализ 4:на 5:ферритин». Ответ — группы номеров подряд идущих слов, по группе на услугу:
  `{"phrases": [[3, 4, 5]]}` или `[[5]]`; «ни одной услуги» — `[]`. Фраза = `reply[start(первого):end(последнего)]` — подстрока
  реплики по построению, выдумать её нельзя; проверка — номера в диапазоне, группы подряд и не пересекаются. Строки прайса к фразе —
  по данным (`phrase_rows`), как сейчас.
- **Почему не окна по данным.** Проба 22.10 (30 ценовых вопросов эталона): фильтр «в окне только слова из названий каталога» срезает
  «Сколько стоит», «Хочу сдать», но теряет слова пациента, которых в названиях нет, — именно там нужен смысл: «Можно ли сделать
  кардиограмму?» → «ли сделать», «Флороценоз» → пусто, «полный чек ап организма» → «полный», «организма»; и оставляет «цена»,
  «стоимость», «в один день» (есть в названиях). Частота в каталоге «общее слово» тоже не определяет (findings §9). Значит, границы
  услуги в реплике — решение LLM целиком; данные — только строки к выбранной фразе.
- **Общие слова решает LLM.** «анализы крови», «услуга», «процедура» — LLM размечает их как услугу или нет (исход «ни одной» —
  не услуга); правила и списки не участвуют.
- **Политика сбоя — у читателей (этап 2).** Разбор при сбое LLM отдаёт `unavailable` без разреза, но понимание хода тогда
  берёт прежний путь правил (`understand_price_turn`) — буквы. «Без LLM — оффер / уточните» выполняют читатели на этапе 2.
- **Генератор окон уходит:** W, фрагменты по разделителям, окна сегментации, сильные окна, варианты (д), `_WRAPPER`, `_FILLER`,
  `_MENTION_EDGE`, `bare()`, `_only_wrapper_outside` — вместе с тремя списками цены как их источником для разбора.
- **Одно решение LLM на ход** (13.10 Q4) — сохраняется. Потолок 16 фраз (13.10 Q3) — как ограничение ответа (не больше 16 групп).
  Длина реплики — потолок слов (как `_MAX_TEXT`), длиннее — `too_many`, оффер.
- **Без LLM** (новое решение): действует только дословное совпадение с данными (`strong_whole`, `strong_all` — название, синоним,
  код клиники: пациент сам назвал строку); остальное — `unavailable` без разреза, читатели — оффер / «уточните название».
  `fallback_split` (разрез по разделителям и сильным окнам при сбое) снимается.
- **Решения, которые сохраняются как механика:** фраза ⊂ реплика (`reply[start:end]`), скобки не рвутся, «ФЕРРИТИН ГЛЮКОЗА
  ХОЛЕСТЕРОЛ» решает выбор (13.10 Q2), слияние списка в одну слабую фразу при разрезе — сбой (`MERGED`).
- **Стеммер этапу 1 не нужен** (ни списков, ни словаря); `russian_nlu.stem_ru` (Snowball) — кандидат на одну нормализацию
  поиска строк по данным в этапе 2, вместо четырёх самописных.

Мерило: набор «падежи» (real), Recall@pool (`rp_6883d19_*` — база), test/dev cached против прода; разбор каждого отличия.

## 3. Этап 2 — потребители читают фразы разбора

Каждый потребитель — свой выключатель, карточка, неделя, снятие выключателя и старого пути со списками. Разбор нужен на всех ходах
с услугой (сейчас — только цена и подбор анализов): подготовка, где сделать, врачи по услуге, акции, walk-in — +1 решение LLM на
ход (бюджет решений хода — см. решение 3 → 4 по журналу 23–24.10). Потребители независимы по файлам — можно параллельными сессиями.

- **Подготовка — `prepare_by_parse` (24.10, STEP-2026-10-24-PREPARE-BY-PARSE).** Разбор строится и на ходу подготовки
  (`observe_prepare_turn`, без понимания для ценовых читателей); предмет памятки — фразы разбора; ни одной услуги — без поиска по
  словам (контекст L-14 или общая памятка о крови как вариант LLM); сбой — «уточните». Общее слово внутри фразы («анализ на …»)
  весит по редкости в памятках МИС, памятка годна, только если в ней есть самое редкое слово фразы; данные МИС — по хвостам фразы
  (словарь синонимов чувствителен к словоформе слов перед синонимом). Пять списков путь `on` не читает (AST по графу вызовов).

## 4. Этап 3 — имена

Фамилия врача — список врачей МИС (данные); фамилия и ФИО пациента (результаты анализов, запись) — разбор LLM (сущности
классификатора) с проверкой «это подстрока реплики»; без LLM — «уточните». Отдельно от этапов 1–2: другие файлы.

## 5. Порядок и риски

- Этап 1 трогает `_turn_phrases`, `turn_understanding`; ветка снятия выключателей (`claude/2026-10-22-switch-removal`, слияние
  27–28.10) — `_price_select_llm`; пересечения нет. Цена (этап 2) — после слияния (консилиум 22.10).
- Риск этапа 1 — Recall@pool разбора (верная фраза не попала в окна) и задержка (больше окон — длиннее промпт); мерить до включения.
- Риск решения (а) — больше офферов при сбое LLM; сбой LLM на проде редок (журнал), но при инциденте GPU бот станет чаще звать
  оператора — это осознанная цена «без угадывания по буквам».

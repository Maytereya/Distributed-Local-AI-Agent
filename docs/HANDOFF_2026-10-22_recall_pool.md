# Recall@pool пути цены — замер по пулу из хода (22.10)

Ветка `claude/2026-10-22-recall-pool` от `release` = `389ffd4` (прод, деплой 15). Коммиты: `c38e7ed` (запись пула в
журнал хода), `6883d19` (детектор и раздел карточки). Без реплик пациентов: только id вопросов набора и счётчики.

## Что сделано

- **Запись, не логика.** `_price_select_llm._ask` — единственная точка вызова `choose()` выбора строки прайса — пишет в
  строку хода поле `price_pool`: `[{"r": круг, "n": размер, "ids": [serviceId…]}]` (`turn_telemetry.note_price_pool`).
  Круг 1 — пул по реплике, круг 2 — по терминам LLM. Сборка и выбор не тронуты, ветки `by_meaning` тоже: с веткой
  снятия выключателей (`claude/2026-10-22-switch-removal`) пересечений по строкам нет.
- **Детектор** `evalbench.detectors.pool_recall`: пул хода ∩ разметка цен (`labels/price_allowed.jsonl`, core ∪ ok).
  Одна услуга — 0/1, список (`multi`) — доля услуг core в пуле. Нет записи пула (LLM строку не выбирала) — отдельный
  счётчик, не 0%. Вне замера `not_price`, `context_dependent`, `absent`.
- **Срезы:** «слово в словаре клиники» (в реплике есть ключ `serviceSynonyms` среза мира — `ClinicSynonyms`, считается по
  данным, не кодом бота) / «вне словаря» / «список услуг» (`multi`) / «всего». «Прочее» вынесено в «без пула»: вопрос
  размечен, но выбор строки LLM на нём не звался (сильная фраза, корзина, не цена).
- **Карточка** (`python -m evalbench.card A B`): раздел «Recall@pool (цена)» — 1-й круг / с 2-м, вопросов с пулом /
  размечено, размер пула 1-го круга (среднее / p90), вызовов 2-го круга; при двух прогонах — id вопросов, выпавших из
  пула и вошедших в него, по кругам.
- **Тесты на класс:** `tests/test_price_pool_record_class.py` (через эндпоинт, оба круга: запись = ровно то, что видела
  LLM; с выключенной записью ответ, пулы и решения хода те же; телеметрия off — записи нет) и синтетика детектора,
  среза и сравнения в `tests/test_evalbench.py`.
- **Гейт** на каждом коммите: ruff 0, pytest `-n auto` 0 (5949 passed / 13 xfailed на `6883d19`).

## Замер базы (прод-набор деплоя 15)

Мир 20261008 day, режим cached, выключатели прогона `d15_all_*` (поле `cfg` их `run.json`), код `6883d19`.
Прогоны `~/Dev/dla-private/bench/runs/rp_6883d19_{test,dev}`: valid=true, живых вызовов LLM 0, словарь 854.

**Запись ничего не меняет:** против `d15_all_*` (код `86d1733`) ответ отличается в **0 из 201** (test) и **0 из 867**
(dev); чужая цена 1 → 1 / 6 → 6, «верная одна», «список с нужной», «покрытие core» — без изменений.

| Срез | test: 1-й круг / с 2-м (с пулом / размечено) | dev: 1-й круг / с 2-м (с пулом / размечено) |
|---|---|---|
| слово в словаре клиники | 50% / 100% (2/8) | 85% / 85% (13/41) |
| вне словаря | 100% / 100% (15/18) | 81% / 93% (70/119) |
| список услуг | 75% / 75% (2/21) | 81% / 81% (8/95) |
| **всего** | **92% / 97% (19/47)** | **82% / 91% (91/255)** |

Размер пула 1-го круга: test — среднее 17,1, p90 24; dev — 15,3, p90 24 (потолок `_POOL_LIMIT` = 24). Второй круг
звался 2 раза на test и 20 раз на dev; на dev он вернул в пул 8 вопросов «вне словаря» (81% → 93%): g0106, g0113,
g0218, g0220, g0452, g0587, g0625, g0669.

**Поправка детектора (тот же день, коммит после `a6b284a`).** Первая версия карточки считала промахом и записи пула
из выбора услуги записи (`judge_booking_service`, тот же `select_price_rows` по каталогу услуг записи): у его строк
нет `serviceId`, и пересечение с разметкой всегда пусто. Такие записи (`n > 0`, `ids` пуст) — не пул ответа о цене,
детектор их пропускает, вопрос уходит в «без пула». Первые цифры (dev 66% / 73% на 113 вопросах) — с этой ошибкой.
Пустой пул цены (`n = 0`) по-прежнему промах.

### Как читать

- **Покрыта только часть размеченных вопросов: 91 из 255 на dev.** Без пула 164:
  - 73 — корзина: их ведёт выбор корзины (`choose` с задачей `price_basket`), а не `select_price_rows` (72 списка +
    1 «в словаре»);
  - 16 — сильная фраза: код решает без LLM (13 «в словаре», 3 «вне»);
  - 47 — ход ушёл не в цену (оффер, адрес, TEST_ASSIST…; 34 из них «вне словаря»);
  - 22 — ход ушёл в запись или адрес, и выбор шёл по каталогу услуг записи (`judge_booking_service`);
  - 6 — ценовой ход без выбора строки по иной причине.

  На test без пула 28: корзина 17, сильная фраза 2, не цена 6, выбор услуги записи 2, иное 1. Поэтому строка «список
  услуг» сейчас описывает только списки, дошедшие до выбора строки (8 из 95 на dev), а не путь корзины.
- **Выборка срезов маленькая.** «В словаре» на dev — 13 вопросов с пулом, на test — 2; один вопрос там — 8–50 п. п.
  Слова из словаря клиники чаще решает сильная фраза (до LLM не доходят).
- **Промах пула почти всегда честный.** На dev 10 вопросов с пулом без эталона даже после 2-го круга: 6 без цены,
  1 список с нужной, 1 одна цена вместо списка, 1 чужая, 1 список без нужной. Эталона вне прайса мира среди них нет.
  - в словаре: g0381, g0612;
  - вне словаря: g0043, g0225, g0398, g0419, g0499;
  - списки: g0254, g0255, g0354;
  - test: g0851 (список).
- **Общее слово вытесняет услугу из пула** — главный видимый класс промахов (разбор вручную, без реплик):
  - g0612 — «фактор» тянет «Фактор IX / XII / VIII / Виллебранда», эталон «Rh- принадлежность» не попадает;
  - g0499 — «заболевания» тянет панели «Наследственные заболевания …», эталон ЗППП не попадает;
  - g0225 — «без анестезии» тянет строки «(без стоимости анестезии)», эталон ФГДС не попадает;
  - g0398, g0043 — пул забит «Анализ крови / мочи …», эталона (гемостазиограмма, ЗППП) нет;
  - g0419 — «эхо сердца»: в пуле «Эхокардиография … плода», базовой «Эхокардиографии» нет.
- **test — один раз на решение** «катить / не катить»; решения — по dev и по поимённым переходам карточки.

## Как пользоваться (до/после снятия выключателей 27–28.10)

```bash
./venv/bin/python -m evalbench.run --set ~/Dev/dla-private/golden_v1.jsonl --set ~/Dev/dla-private/golden_v1_random.jsonl \
    --split dev --code-root <дерево> --world 20261008 --profile day --mode cached --name <имя>_dev <--cfg из run.json d15_all_dev>
./venv/bin/python -m evalbench.card rp_6883d19_dev <имя>_dev
```

Сравнивать с `rp_6883d19_*` (не с `d15_all_*`: там пула нет — карточка честно пишет «пул не записан»). Дерево кода для
«после» должно включать `c38e7ed`: без записи пула замера нет. Режим down тоже пишет пул 1-го круга (он пишется до
вызова LLM), но второго круга в нём нет.

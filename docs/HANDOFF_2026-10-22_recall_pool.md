# Recall@pool пути цены — замер по пулу из хода (22.10)

Ветка `claude/2026-10-22-recall-pool` от `release` = `389ffd4` (прод, деплой 15). Коммиты: `c38e7ed` (запись пула в
журнал хода), `6883d19` (детектор и раздел карточки). Без реплик пациентов: только id вопросов набора и счётчики.

## Что сделано

- **Запись, не логика.** `_price_select_llm._ask` — единственная точка вызова `choose()` выбора строки прайса — пишет в
  строку хода поле `price_pool`: `[{"r": круг, "n": размер, "ids": [serviceId…]}]` (`turn_telemetry.note_price_pool`).
  Круг 1 — пул по реплике, круг 2 — по терминам LLM. Сборка и выбор не тронуты, ветки `by_meaning` тоже: с веткой
  снятия выключателей (`claude/2026-10-22-switch-removal`) пересечений по строкам нет.
- **Детектор** `evalbench.detectors.pool_recall`: пул хода ∩ разметка цен (`labels/price_allowed.jsonl`, core ∪ ok).
  Одна услуга — 0/1, список (`multi`) — доля услуг core в пуле. Нет записи пула (LLM строку не выбирала) — отдельный
  счётчик, не 0%. Вне замера `not_price`, `context_dependent`, `absent`.
- **Срезы:** «слово в словаре клиники» (в реплике есть ключ `serviceSynonyms` среза мира — `ClinicSynonyms`, считается по
  данным, не кодом бота) / «вне словаря» / «список услуг» (`multi`) / «всего». «Прочее» вынесено в «без пула»: вопрос
  размечен, но выбор строки LLM на нём не звался (сильная фраза, корзина, не цена).
- **Карточка** (`python -m evalbench.card A B`): раздел «Recall@pool (цена)» — 1-й круг / с 2-м, вопросов с пулом /
  размечено, размер пула 1-го круга (среднее / p90), вызовов 2-го круга; при двух прогонах — id вопросов, выпавших из
  пула и вошедших в него, по кругам.
- **Тесты на класс:** `tests/test_price_pool_record_class.py` (через эндпоинт, оба круга: запись = ровно то, что видела
  LLM; с выключенной записью ответ, пулы и решения хода те же; телеметрия off — записи нет) и синтетика детектора,
  среза и сравнения в `tests/test_evalbench.py`.
- **Гейт** на каждом коммите: ruff 0, pytest `-n auto` 0 (5949 passed / 13 xfailed на `6883d19`).

## Пул корзины (22.10, вечер): списки покрыты

Ветка `claude/2026-10-22-recall-pool-basket` от `a6b284a`. Коммиты: `332cc62` (запись пула корзины), `3c72e3a`
(детектор и подпись карточки). Гейт на каждом: ruff 0, pytest `-n auto` 0 (5956 / 5957 passed, 13 xfailed).

- **Запись, не логика.** `_basket_select._pick` (обе корзины — из фраз разбора и корзина правил) пишет в то же поле
  `price_pool` одну запись `{"r": 1, "src": "basket", "n", "ids", "strong"}`: `ids` — `serviceId` вариантов, которые видит
  LLM корзины, в их порядке; `strong` — строки сильных позиций, решённые данными без LLM. LLM корзины не звалась (все
  позиции сильные, вариантов нет, режим `strict`) — `ids` пусто, `n` = 0. Записи выбора строки — без `src`, как были.
  С `claude/2026-10-22-switch-removal` по строкам не пересекается (там `_ranked` и импорты).
- **Детектор:** потолок ответа списка — варианты LLM корзины ∪ сильные строки (сильные идут в ответ как есть, без них
  список из трёх сильных и одной слабой позиции показывал бы ≤25%). Корзина без вызова LLM — пул записан, в размер
  пула (по вызовам LLM) не входит.
- **Тест на класс** `tests/test_basket_pool_record_class.py` (через эндпоинт): запись = варианты подсказки LLM корзины
  по порядку, `n` = `options` решения `price_basket`; строки с ценой в ответе корзины — только из `ids ∪ strong`;
  с выключенной записью ответ, подсказки и решения хода те же; LLM недоступна (корзина правил) — запись есть.

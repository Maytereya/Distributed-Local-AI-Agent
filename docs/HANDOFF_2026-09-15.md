## 1. Правила работы

- **Атомарные коммиты.** Один фикс — один коммит.
- **Гейт: `ruff` + полный `pytest`.** Коммит только по ЗЕЛЁНОМУ. Читать фактический
  exit-код и сводку: статус «completed» у фоновой обёртки **не равен** зелёному прогону.
- **К каждому гарду — встречный свип по живым данным.** Целевой тест гарда не видит,
  что тот глушит корректное. 15.09 свип поймал подмену онкомаркера анализом на
  кальций (182 названия каталога из 1200) при зелёных целевых тестах.
- **Промпты в ДВУХ локациях** — `messengers_router/prompts/*` и `app_data/prompts/mr_*`.
- **Баги — в `docs/messengers_router_bug_log.md`**: симптом · корень · фикс ·
  **инвариант класса** · покрытие. Тесты на КЛАСС, не на инстанс.
- **NLU чинить LLM-first**, не стоп-листами под одну фразу.
- **Прод-движок NLU = `legacy_v2`**, rule-path активен.
- Репозиторий **публичный**: не коммитить ПДн, учётные данные, прод-топологию.
- Рассуждать можно по-английски, **выводы и план — по-русски**.

## 3. Приёмы диагностики (экономят часы)

**Ошибка прода читается из HTTP-ответа, SSH не нужен:**

```python
payload = {"session_id": "diag", "text": "...", "debug": True}
# → state_update.debug.route_error  — текст исключения из endpoint.py
```

15.09 это дало корень за минуты вместо часов.

**Живой прогон бота:** `http://172.16.0.28/api/messenger-generate-once`.
**Состояние ollama:** `http://172.16.0.28:11434/api/tags` и `/api/ps` (доступны с Mac).
**Офлайн-репро цен без VPN:** каталог `price_region_3_*.jsonl`, звать
`resolve_price_service_name_from_catalog(q, rows=rows)` напрямую.
**Проверка живости:** `./venv/bin/python scripts/check_bot_health.py --url ...`

**Ловушка:** проверять «без авторизации» тем же `requests.Session`, которым уже
ходил с Basic — в сессии остаются куки, и запрос оказывается авторизованным.
Каждый случай мерить ЧИСТОЙ сессией.

## 4. Очередь работ

### №1 — «кровь на сахар» отдаёт аллергопанель `[ПРИОРИТЕТ]`

«Кровь на сахар» → **«Свекла сахарная (F227)» 650 руб.** вместо Глюкозы 190.
Три другие формулировки («сахар», «сахар крови», «анализ на сахар») клиника
починила данными — эта держится анти-перехватом: в остатке остаётся «кровь», а
его нет в речевой обвязке.

**Нельзя** добавить «кровь» в обвязку — оно значимо в названиях («Группа крови»,
«Кровь на ВИЧ»). **Правильный путь:** засчитывать в остатке слова-биоматериалы по
словарю `biomatNames` МИС (заполнен у 98%). Данные из МИС, никаких списков в коде.
Мешает то, что `split_biomaterial_tail` снимает ХВОСТ, а тут «кровь на» спереди.

### №2 — Сузить `except Exception` в доборе синонимов

`backfill_service_synonyms` ловит `Exception` целиком. 15.09 это спрятало
`AssertionError` из теста и дало ложный зелёный. Завтра спрячет ошибку в коде.
Ловить сетевые/HTTP, остальное пробрасывать.

### №3 — Прод-логи за два месяца → частотный список синонимов

Скрипт готов: `scripts/extract_synonym_candidates.py`. Нужна выгрузка:

```bash
docker logs --since 1440h support-messenger-aggregator-telegram_bot-1 > /tmp/prod60d.log
```

Логи содержат ПДн — в репозиторий не класть, выходной файл смотреть глазами.
Рабочий лист на 148 услуг уже собран: `docs/synonyms_to_fill_2026-09-15.csv`.

## 5. Чего НЕ делать

- Не искать причину прод-проблем в коде роутера по одной вилке дат. Сначала
  `debug=True` → `route_error`, потом `main_model.txt`, потом ollama.
- Не приравнивать «мазок» и «посев» — 290-510 руб. против 1120.
- Не добавлять ручных синонимов услуг: только из МИС.
- Не идентифицировать услугу по биоматериалу (44 услуги на один соскоб).
- Не снимать гард family-mode для витаминов целиком — сломает точное попадание
  «витамин Д». Ослаблять ТОЛЬКО на неоднозначном коде.
- Не ослаблять eval-кейс, если бот ответил не по существу. 15.09 кейс про
  вульвоскопию оставлен красным намеренно: бот объяснил, ЧТО это, вместо того
  как подготовиться. Это разброс качества, а не хрупкость формулировки.

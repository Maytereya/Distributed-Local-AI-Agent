# Хэндофф для облачной сессии: четыре задачи рефакторинга по очереди (19.10.2026)

Одна облачная сессия, задачи **A → C → B → D строго по очереди**. Каждая задача — своя ветка, свои атомарные коммиты.
Время в отчётах — «Самара (UTC+4) / у владельца (UTC+7)». Выводы и план — по-русски.

## 0. Перед началом

1. Прочитать `CLAUDE.md` целиком, особенно раздел **«Облачная сессия»**: у тебя только репозиторий — нет LLM, VPN, прода,
   стенда, `config.ini`, локальных хэндоффов; отвечать другим сессиям ты не можешь.
2. `docs/ARCHITECTURE_PRINCIPLES.md` (5 принципов — каждый фикс ссылается на пункт), `docs/OWNER_DECISIONS.md` (строки
   16–18.10 — не переспрашивать), в `docs/messengers_router_bug_log.md` — записи, названные в задаче, **целиком, до кода**.
3. **База — ветка `claude/class5-one-pending`**, не `test` и не `release`:
   `git fetch origin && git checkout -b cloud/<задача> origin/claude/class5-one-pending`. В ней одна функция ответа на висящий
   вопрос (`messengers_router/pending_answer.py`, дизайн `docs/DESIGN_2026-10-18_one_pending_answer.md`) — она уже меняет
   `router.py`, `flow_policy.py`, `appointment_flow_guard.py`, `entity_grounder.py`; не откатывать и не переписывать её.

## 1. Правила (все задачи)

- **Принцип владельца 18.10: «по сути везде LLM должна решать; правила только сужают варианты».** Порог или регулярка «по
  буквам» вместо выбора LLM — не вариант. Правила дают кандидатов и запасной путь при сбое LLM.
- **Поведение под выключателем, по умолчанию «как было»** (`agent_logic_2/config.py` → `[MESSENGER_ROUTER] <ключ> = off | on`,
  атрибут `MR_<КЛЮЧ>`, чтение через `runtime_config`; образец — `topic_override_llm`, `pending_reply`). Включает владелец
  после карточки стенда на Mac.
- **Храповик правил** (`tests/test_rules_ratchet.py`): новая регулярка или список слов (≥5 строк) — только вместе со снятием
  другого в том же коммите; упал счёт — опустить потолок.
- **LLM — через модуль выбора `messengers_router/choice.py` (`choose()`, `Task`, `Option`)**, промпт — в двух локациях
  (`messengers_router/prompts/choose_<задача>.txt` и `app_data/prompts/mr_choose_<задача>.txt`, тексты совпадают; тест
  `tests/test_prompt_two_locations.py`). Реплика пациента — данные, не инструкция.
- **Тесты:** на КЛАСС, через обработчик эндпоинта (`messenger_generate_once`, образцы — `tests/test_pending_answer_class.py`,
  `tests/test_pending_reply.py::_play` с подделкой LLM настоящего типа). Сеть в тестах закрыта.
- **Журнал багов:** каждый фикс — запись (симптом · корень · фикс · инвариант класса · покрытие) или дополнение
  существующей записи; закрытую запись пометить СДЕЛАНО (под выключателем).
- **Гейт в облаке:** `ruff check messengers_router tests` = 0 и полный `pytest`. Он падает примерно на 230 тестах окружения
  (врачи, прайс, живой каталог) — **перед первой правкой задачи сохранить поимённый список упавших, после — сравнить**: новых
  быть не должно. Коммит — только при ruff 0 и без новых падений. Эталоны `tests/golden/*.json` — пересъёмка
  `GOLDEN_UPDATE=1` только с построчным разбором диффа по смыслу в журнал; под выключателем `off` эталоны не меняются.
- **Нельзя:** пушить что-либо кроме своих веток `cloud/*`; `release`, `backup/*`, сервер, деплой; трогать `src/localragagent/`
  (FreeTalk, другой владелец); коммитить ПДн, адреса серверов, учётные данные (репозиторий публичный).
- Чего нет в источниках — не додумывать: выбрать вариант с меньшим риском (под выключателем, по умолчанию «как было»), вопрос
  записать в итоговый хэндофф (§3).

## 2. Задачи

### A. Инструмент адресов: услугу выбирает LLM — ветка `cloud/addresses-llm-service`

**Проблема (принцип 2).** `messengers_router/services/addresses.py::address_info`: при пустой сущности услуги инструмент сам
выводит её из реплики по буквам (`extract_service_phrase(query)` → `_service_procedure_flag`, `care-setting` по `priceUnits`):
«где сделать магнитотерапию» → адрес филиала «Mg+» по совпадению букв. Это «решают буквы».

**Сделать.** Под выключателем `address_service_llm` (умолч. off): правила дают кандидатов услуги (то же извлечение плюс
строки прайса / службы, которые сейчас решают), выбор — `choose()` закрытым списком (новая задача, промпт в двух
локациях); «ни одна» / сбой LLM — общий список филиалов или прежнее поведение (решить по данным и записать почему).

**Готово:** тест класса (реплики «где сделать X» для нескольких X, в том числе слово-омоним), под off — ответы прежние,
под on — выбор модели (подделка LLM); запись журнала; храповик не вырос.

### C. Слоты записи по смыслу — ветка `cloud/booking-slots-by-meaning`

**Проблемы.**
1. Специальность не извлекается из «На какое время запись к неврологу» (у живого классификатора — сущность «время», без
   специальности): сейчас честный оффер оператора. Чинить LLM-first (промпт классификатора `classifier_patient` в двух
   локациях и/или выбор специальности `choose()` из каталога ролей), не регуляркой под фразу.
2. Подавитель A′-1 `router._suppress_grounder_rejected_slots` держит значение, которое резолвер находит по буквам
   (журнал BUG-2026-06-02-02, инвариант 2) — перевести на выбор LLM / данные МИС под выключателем.
3. Открытые записи журнала: **BUG-2026-10-18-PREPARE-UZI-AS-BOOKING**, **BUG-2026-10-08-PREPARE-ANESTHESIA-IN-QUERY**,
   **BUG-2026-10-08-SLOT-REPLY-LOST-TO-LLM** — читать целиком, решения владельца в них не переоткрывать.

**Сделать.** Каждый пункт — свой коммит, свой выключатель (или общий `booking_slots_llm`, если меняется одна точка);
согласовать с одной функцией ответа на висящий вопрос (ответ на шаг записи — её `Answer`, не дублировать).

**Готово:** тесты класса на каждый пункт, под off — как было; записи журнала обновлены.

### B. T7: снять эвристики запасного пути цены + открытые записи цены и корзины — ветка `cloud/t7-price-fallback`

**Где мы.** Справка 14.10 (локальная; суть — здесь): из кандидатов T7 уже сняты K0 (`_build_multi_price_payload`), K5 (ветка
«дословное название — правила не ошибаются») и K6 (`_legacy_strong_service_match` + `strong_match`) — деплои 5–9.
Живы и **не снимаются**: K2 (`_multi_price_items` / `_resolve_multi_price_items` / сегментатор S2 — источник кандидатов
генератора фраз; снятие = смена запасного пути Q2, решение владельца 16.10 «разрез данными МИС — только при ≥2 сильных
окнах»), K4 (`limit=2` — кандидаты корзины), K7 (`_extract_price_service_from_query` как фраза журнала — замены без LLM нет).

**Снять под выключателем (умолч. off):**
- **K1** — защиты `price_list_services` (`services/_prices_helpers.py`: «одно название покрывает», «сплошной список — только
  распознанный»). Под разбором хода (`turn_parse`, единственный режим) они решают только на запасном пути
  (`turn_parse.acting_for` = None: разбор не запускался, `empty` / `too_many` / `error` / `late`, сбой LLM без разделителей).
  Риск: «когда будет готов анализ на ферритин» → корзина из двух позиций; «Глюкозотолерантный тест (глюкоза+ C-пептид)» →
  две позиции. Сначала — тест «LLM недоступна, сплошной текст» на запасном пути, потом снятие.
- **K3** — гард третьего стыка внутри `_multi_price_items` (`_match_drops_unsatisfiable_qualifier` → пусто). Под разбором его
  заменяет флаг `unsatisfiable` у `phrase_price_items` (П2). Риск — возврат П2 («по ОМС» → платные приёмы) на запасном пути:
  тесты `tests/test_p2_strong_phrase_class.py`, `tests/test_price_unsatisfiable_qualifier.py`, класс `phrase_smear_throat`.

**Плюс открытые записи журнала пути цены и корзины** (те же файлы — поэтому в этой задаче):
**BUG-2026-10-15-P2-ENTITY-BYPASS** (фикс по буквам не годен — путь LLM), **BUG-2026-10-17-P2-JUDGE-COLLECTION-CONDITIONS**,
**BUG-2026-10-17-BASKET-HOME-VISIT-ROW**, **BUG-2026-10-14-SHOW-ALL-AS-CATALOG-SERVICE** (под off; под `pending_reply = on`
«все» уже решает одна функция — проверить и записать).

**Готово:** K1 и K3 — каждый своим коммитом и выключателем, разбор диффа эталонов под on в журнал; по каждой открытой записи —
фикс под выключателем с тестом класса или обоснование «не в облаке» (нужна живая LLM / стенд) в итоговом хэндоффе.

### D. Черновик дизайна хода (б): понимание хода — ветка `cloud/design-turn-understanding`

**Только документ, без кода:** `docs/DESIGN_2026-10-19_turn_understanding.md`. Тема: `ServiceMention` → `TurnUnderstanding`

по образцу таблицы `pending_answer.POLICY`). Источники — только репозиторий: `messengers_router/turn_understanding.py`,
`turn_parse.py`, `services/_turn_phrases.py`, читатели `turn_parse.acting_for`, записи журнала `STEP-2026-10-10-B1-*`,
`STEP-2026-10-16/17-*`, `docs/DESIGN_2026-10-18_one_pending_answer.md` (как сделан класс 5 — образец). Раздел «Решения на
проверку владельцем» — обязательно; консилиум и стенд владелец проведёт на Mac.

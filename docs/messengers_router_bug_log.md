# `messengers_router` — журнал багов (anti-regression log)

**Зачем:** все присланные «живые» баги фиксируются здесь, чтобы код не регрессировал и баг не приходил повторно. Ключевой принцип — **записываем не только инстанс, но и обобщённый инвариант** (класс бага), и покрываем его **тестом на класс**, а не на конкретный случай.

**Почему не только тесты:** инстанс-тест (на «Турмухамбетова») ловит один случай — другой несамарский врач воспроизведёт баг, а тест пройдёт. Поэтому:
1. **Тест на КЛАСС/инвариант** — параметризованный, или сканирует live-кэш и выбирает отсутствующего, или использует синтетическое значение, гарантированно попадающее в класс.
2. **Локальные тесты держат детерминированную логику; remote eval держит live/LLM-поведение** (то, что локально не воспроизвести). Golden-кейсы в `eval_suite/` добавляются по решению владельца.
3. Запись здесь = «память проекта» по багам (версионируется, видна команде, переживает сессии).

**Формат записи:** симптом (как прислал пользователь) · корень · фикс-коммит · **инвариант** · покрытие (тест/eval).

## BUG-2026-07-13-УЗИ (процедурный запрос → простыня всех врачей; повтор до анти-луп) — «УЗИ органов мошонки»

- **Симптом (прод-диалог 08.07):** «УЗИ органов мошонки» → ВСЕ 4 УЗИ-врача с полными CRM-описаниями (~12К символов; телеграм резал ответ на 2 сообщения), включая врачей БЕЗ этой процедуры; «Кого рекомендуешь» и «Кто из них топ» повторяли тот же список, на 3-м идентичном ответе сработала анти-луп защита (оффер оператора — штатно).
- **Корни (четыре, класс):**
  1. Ветка `rule_doctor_info_specialty` (наследие фев-2026) оставляла ТОЛЬКО specialty — процедурная конкретика отбрасывалась; более специфичное правило `rule_doctor_info_service` требует обёртку «кто/какой врач делает».
  2. Даже переданный `service_name` **молча дропался граундером**: `_LABEL_ENTITY_WHITELIST["DOCTOR_INFO"]` не содержал `service_name`.
  3. `_doctor_matches_service` пропускал чужих врачей по generic-токенам: «УЗИ ОРГАНОВ мошонки» матчил Ларионову по «узи»+«органов» («органов малого таза») без «мошонки» — нарушение принципа «различающего токена» (BUG-2026-06-09-04).
  4. `_compact_specialization` вызывался с выключенными лимитами (полный текст CRM-«уточнения», 1.5К+ символов на врача).
- **Фиксы:** specialty-ветка передаёт `service_name`, если фраза-услуги специфичнее специальности (`rule_doctor_info_procedure_detail`); `service_name` в DOCTOR_INFO-whitelist граундера; различающий токен обязателен в `_doctor_matches_service` (`_PROCEDURE_GENERIC_TOKENS`); список врачей компактный — при процедурном запросе в карточке РЕЛЕВАНТНЫЕ строки описания (`_compact_specialization_service_lines`), полное описание только по конкретному врачу.
- **Рекомендации врача (LLM-first, по решению владельца):** кейс в промпт классификатора («Кого рекомендуешь», «Кто из них топ» → OTHER conf 0.9) + гард в оба рендер-промпта («не выбирай и не сравнивай врачей — предложи расписание»). Живая проверка: «Кого рекомендуешь» → «Все врачи нашей клиники квалифицированы. Могу помочь с записью…» ✅.
- **LLM-путь (rule=None), живые пробы:** «где сделать узи мошонки» → ADDRESS + нормализованная услуга ✅; «узи мошонки что за процедура» → DOCTOR_INFO, но конкретику терял (добавлена промпт-инструкция «заполняй specialty И service_name», прод-проверка после деплоя); «хочу проверить яички на узи» → APPOINTMENT с пустыми entities и кривым ответом «этого врача нет» — **открытый хвост**: разговорные синонимы частей тела (яички→УЗИ мошонки) LLM не мапит стабильно; кандидат — курируемая мапа синонимов процедур (как забор→взятие) + починить APPOINTMENT-ответ при пустых entities.
- **Инвариант (класс):** процедурный запрос отдаёт ТОЛЬКО врачей, реально делающих процедуру (различающий токен обязателен), компактно (карточка с релевантными строками, ответ в один месседж), полное описание — по конкретному врачу; просьба рекомендации не повторяет список и не сравнивает врачей.
- **Живой прогон после фикса:** «УЗИ органов мошонки» → 4 врача С процедурой (Казакова, Портянникова, Калашникова, Белохвостикова), в карточках строки про мошонку, 693 символа (одно сообщение).
- **Покрытие:** `tests/test_doctor_info_procedure_detail.py` (7: роутинг с конкретикой/без, фильтр с приманкой «органов малого таза», компактность списка, полное описание врача, e2e через run_pipeline — ловит дроп граундера).
- **Примечание про «нарезку агрегатора»:** подозрение, что агрегатор повторно шлёт первый кусок, НЕ подтвердилось — в диалоге оба куска приходили каждый раз; ответы бота реально были идентичны (детерминированный повтор), а резка — штатный телеграм-лимит 4096. После компактизации ответ влезает в одно сообщение.

## FEAT-2026-07-06-П9 (faithfulness, инцидент 25.06) — «больничный лист» → перевод на оператора вместо галлюцинации «клиника не оформляет»

## FEAT-2026-06-26-П6 («корзина анализов», закрывает ядро BUG-B) — мульти-список анализов распознаётся целиком; сегментация сплошного списка ПО КАТАЛОГУ; честный «не распознал»

- **Контекст (триаж BUG-B):** список «ОАК +СОЭ ОАМ ОБЩИЙ БЕЛОК … Сколько будет стоить?» (30 позиций, CAPS, переносы, опечатки) распознавался как ОДНА позиция → ответ про первый анализ. Корень: сплиттер `_split_price_query_items` резал только по `, ; + / и` (ни `\n`, ни маркеров), сплошной токен-ран не делился вообще; <2 фрагментов → молча single-путь.
- **Фикс (S1-S3, `_prices_helpers.py`):**
  - **S1:** `\n` и `•` — разделители; шумовые фрагменты цены («Сколько будет стоить?», «итого») отбрасываются МОЛЧА (`_MULTI_PRICE_NOISE_RE`) — не услуги и не «нераспознанное».
  - **S2 (ключ):** `_segment_items_by_catalog` — сплошной список сегментируется ЖАДНЫМ longest-match n-грамм (окно 3→1), лексикон = сам прайс («ОБЩИЙ БЕЛОК» — 2 токена, «ОАК» — 1). Гарды от пере-жадности (нашлись в TDD): (а) окна не содержат шум/вежливость (стоп-слова разрывают окно); (б) у многословного окна КАЖДЫЙ содержательный токен обязан находиться в каноне (иначе фаззи-resolve глотал соседей: «ОАК ОАМ ОБЩИЙ»→одна услуга); (в) гард подмены `_scorer_match_has_distinctive_overlap` («Витамин B1» ≠ «Витамин B12» — реальная подмена, пойманная в TDD); (г) курируемые алиасы (ОАК/ОАМ) минуют гарды (точны по построению, канон не содержит букв аббревиатуры). Гейт сегментации: ≥4 токенов и ≥2 распознанных, иначе прежний single-путь (фразы записи не сегментируются).
  - **S3 (честность):** нераспознанные позиции доезжают до пациента строкой «Не распознал: … Уточните эти названия» (`unrecognized_note` в payload + рендер в `_format_price_family_variants`) — неполнота не замалчивается.
- **Инвариант (класс):** мульти-список анализов (переносы/маркеры/сплошной CAPS-ран) отдаёт ВСЕ распознанные позиции с ценами; нераспознанные перечисляются явно; одиночные запросы и фразы записи в multi НЕ уходят; подмена соседней услугой запрещена гардом различающего токена. Опечатки ловит существующий гомоглиф-фолдинг («ЛАКТАТІ»→Лактат).
- **Фикс-коммит:** (хеш в истории: feat(price): корзина анализов S1-S3). **Покрытие:** `tests/test_multi_price_cart.py` (8 тестов на РЕАЛЬНОМ каталоге: \n-список; •-маркеры; CAPS-реплика BUG-B ≥5 позиций; одиночный/запись — не сегментируются; «не распознал» в payload и рендере; отсутствие note без нераспознанных) + регресс BUG-H/синонимов/framing зелёные.
- **Открыто (follow-up):** «Витамин B1 Витамин B6» — гард подмены (B1→B12) отключает сегментацию → прежний single-путь (только B1); обе цены = S4 (LLM-экстракция списка в JSON с верификацией) или digit-точный tie-break в resolve. Pre-existing quirk: `resolve("анти-тг")`→«Анти-ХГЧ» (подмена в САМОМ resolve, вне multi) — отдельная грань класса BUG-2026-06-02-07.

## FEAT-2026-06-26-П5 (вариант B, закрывает «Открыто-1» BUG-2026-06-23-01) — LLM-нормализация услуги к термину каталога: fallback-only + обязательная верификация

## BUG-2026-06-23-01 (распознавание услуги, синонимы/аббревиатуры — класс BUG-2026-06-02-09) — «забор крови из вены» и «электромиография» не находят услугу в каталоге

- **Симптом (живые прод-диалоги 23.06):**
  - Д#403: «сколько стоит **забор** крови из вены» → «Скажите название услуги/анализа — я уточню стоимость» → повтор «забор крови из вены» → тот же переспрос (бесконечный clarify-цикл, пациент не получает цену).
  - «**Электромиография**» → «Не совсем понял ваш запрос…» (OTHER); оператор подхватил вручную («ЭМГ по предзаписи в Самаре, какая область?»).
- **Investigation (systematic-debugging, офлайн-repro по реальному каталогу 3675 строк):**
  - bug 1: услуга ЕСТЬ — «**Взятие** крови из вены» (190р). Пациент сказал «**забор**» (синоним «взятия»). `resolve("забор крови из вены")` → **None**; `resolve("взятие крови из вены")` → находит. Матчер лексический, синоним не мостит.

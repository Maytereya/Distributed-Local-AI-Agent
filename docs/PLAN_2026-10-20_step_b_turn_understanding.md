## 1. Цель и честная граница

**Цель.** Сейчас то, «о чём реплика», решают 4–5 слоёв по очереди: правило классификатора (если сработало — LLM не
зовут), реестр тем, переклейки меток роутера, guardrails, понимание цены. Каждый может переписать предыдущего, следа
решения в одном месте нет. Станет: **одна стадия «понять»** строит `TurnUnderstanding` (тема + источник, упоминания
услуг, свойство вопроса, ожидаемый ответ), остальные только читают его, а меняют — через таблицу политик с записанной
причиной. Тему решает LLM, правила **сужают** (предлагают кандидатов), как в принципе 2.

**Граница.** Безопасность остаётся отдельной ранней проверкой (принцип 4: поднять срочность может любой слой, снять —
никто); кнопки — детерминированное решение; ответ на висящий вопрос — уже одна функция (класс 5). «Один слой» — это
одно место решения и один объект, не один файл.

### 2.3. Что из этого следует

1. **Правила решают тему в 7–8 ходах из 10** — LLM-классификатор работает на остатке. Принцип 2 («правила предлагают,
   LLM выбирает») для темы не выполняется нигде, кроме ходов без правила.
2. **Слои спорят друг с другом в цифрах:** `rule_test_assist` в 43–58% ходов переписывается ПОСЛЕ NLU роутером в PRICE.
   Это прямая цена «4–5 слоёв»: одно решение принимается дважды, второй раз — по флагу каталога. Первый кандидат таблицы
   политик (этап 3).
3. **Где правило уже хорошо** (`rule_price`: чужая цена 1 из 34 и 6 из 131 — это ошибки выбора строки, не темы;
   `rule_test_result`, `rule_address*`: 0% переводов) — снимать первым смысла нет, сначала замер согласия LLM.
4. **Разметки «правильной темы» нет** — эталон размечен по ценам, не по метке. Без неё «LLM решает лучше правила» не
   доказать (вопрос 6, раздел 7).

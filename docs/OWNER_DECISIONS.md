# Решения владельца — журнал (для всех сессий, включая облачные)

Что владелец уже решил о поведении бота и о способе работы — чтобы сессии не переспрашивали и не решали заново.
Только дописывать: новое решение — строкой с датой; отменённое — не удалять, а пометить «отменено DD.MM: …».
Подробности и обоснования — журнал багов (`docs/messengers_router_bug_log.md`) и хэндоффы. Репо публичный: здесь нет
адресов, ключей, топологии и защиты прода.

## Принципы и мера успеха

| Дата | Решение |
|---|---|
| 22.07 | Дезинформация ценой строго хуже уточнения: при неоднозначности — список вариантов, а не одна (возможно чужая) цена. |
| — | Синонимы услуг придумывает клиника; данные — из МИС, в коде — механика, а не словари. |
| 07.10 | LLM может поднимать срочность, но не снимать (монотонная безопасность). Срочное — только «Соединяю с оператором.». |
| 07.10 | Правило ≤3: не больше трёх лишних уточнений или переводов на оператора за одну предотвращённую чужую цену или памятку. |
| 08.10 | Конституция — 5 принципов (`docs/ARCHITECTURE_PRINCIPLES.md`): (1) факты печатает код из МИС; (2) смысл — LLM выбирает номер из найденного кодом; (3) данных нет — честный оператор; (4) безопасность монотонна; (5) бот знает, чего ждёт, и не ходит по кругу. LLM чисел своим текстом не пишет. |
| 08.10 | Мера успеха — трафик: разметка реальных диалогов раз в 2–4 недели («тихий провал», «решено ботом»); откат — «тихий провал» +5 п.п. и больше, значимый рост чужой цены на эталоне, срочное <100%. Эталон (стенд) — ограждение, а не цель. |
| 08.10 | Каждая правка сверяется с планом рефакторинга: совместимые — делать без отдельного вопроса (атомарно, через гейт); противоречащие или рискованные (новый регэксп/словарь, видимое поведение без выключателя) — сначала спросить. |
| 08.10 | Гейт: тест класса через эндпоинт по полному тексту ответа — обязателен для каждой записи журнала багов. |
| 09.10 | Бот — навигатор по клинике, не скорая. Симптом внутри вопроса о клинике, не узнанный регуляркой, срочным не делается. |
| 11.10 | Закон Гудхарта: метрики — ограждение; не подгонять правилами под эталон («а оак» как аббревиатура — нельзя). Храповик правил (`tests/test_rules_ratchet.py`): регэкспов и списков слов не прибавлять; новое правило — только со снятием другого. Настройка — на `split=dev`, решение — один раз на `test`. |
| 14.10 | Тест на два хода — обязательный класс для каждого нового поведения («контекст = показанное»); инвентаризация потребителей понимания (журнал, состояние сессии, телеметрия) — не только производителей решения. |

| 08.10 | Существующую запись пациента бот не ищет и не показывает; «моя запись / проверить / отменить» → оператор, без петель. |

| 10–11.10 | Срок готовности печатает код из МИС: явная единица — дословно; без единицы («1-2», «до 7») — дни, без слова «рабочих». 14.10: дни календарные, день сдачи не считается; текст оставить как есть («1–2 дня»). |
| 10.10 | Симптом → врач: терапевт рядом с профильным — лишний; «сердце колотится», «кровь при походе в туалет» — назвать врача, не переводить. |
| 13.10 | «Сильное совпадение» — только данные МИС: точное название, синоним МИС, код услуги. «Название до скобок» и словарь кода (`_PRICE_SERVICE_ALIASES`) — слабое → выбор LLM; содержимое словаря — клинике как предложения. |
| 13.10 | Политика сбоя LLM для списков: сильные позиции — с ценой; слабая позиция — несколько вариантов кода с полными названиями и ценами; одна-единственная слабая строка не подаётся как «та самая цена». |
| 13.10 | L-15b (`turn_parse`): разбор «одна или несколько» — LLM выбирает фразы из перечня кода; тень — во время хода; без обхода LLM по сильным окнам без разделителей; потолок 16 фраз; лимит 2 решения LLM на ход. |
| 13.10 | Утечка контекста после ответа без цены — вариант (а): услуга снимается из контекста (уточнение вместо чужой цены). |
| 14.10 | Точечные правки под один анализ (например «б12 без головы списка») — нельзя: чинить классом. |
| 14.10 | «Ответ на висящий вопрос бота» — LLM вместо регэкспов «да/нет» (план 07.10, шаг (в)): после `context_shown`, сначала тень, выключатель на каждый тип вопроса; асимметрия безопасности — `docs/DESIGN_2026-10-14_pending_reply.md`. |
| 14.10 | Отмена существующей записи — в том числе ответ «отменить» на «Хотите отменить или перенести запись?» — сразу перевод на оператора со сводкой, без вопроса «Перевести?»: бот не ходит в МИС, запись оператор видит сам. Исправление бага — по умолчанию, без выключателя (BUG-2026-10-14-CANCEL-EXISTING-LOST). Более продуманный механизм — возможно, позже. |

## 2. Как станет

**Одна функция** `pending_answer.answer(state, text, *, button_id) -> Answer | None` в точке нынешней тени (после
срочного и охраны города). Результат — в переменной хода; **все решатели §1 читают `pending_answer.current()`**, своих
правил разбора ответа у них не остаётся.

```text
Answer:
  type      — тип вопроса (_expects.type)
  outcome   — yes | no | pause | new_topic | pick | none
  pick      — текст выбранного пункта (_expects.options) или None
  rest      — хвост реплики для NLU — режет КОД, не LLM (контракт C) — или None
  source    — fast | llm | fallback
```

Порядок внутри функции:
1. **Сужение без LLM (`fast`)** — новых слов нет:
   - вся реплика — голый якорь (`_CONFIRM_YES/NO_EXACT`) — **только у типов «да/нет»** (полярность в `POLICY`: у выборов
     «не нужно» значит своё, например «без наркоза»);
   - «якорь + разделитель + хвост» — самый длинный префикс-якорь до «,», «.», «!», «—», « а », « но »: исход от якоря,
     `rest` = хвост; хвост тем же ходом идёт обычным путём с полным бюджетом;
   - реплика дословно — один из показанных пунктов или его номер → `pick`.
2. **LLM** — `choose()` закрытым выбором: исходы `yes/no/pause/new_topic` + показанные пункты, вопрос бота в данных хода
   (без ПДн, как сейчас). «да, второй» → `pick` (правка `choice._judge`: исход не теряет номер; тест класса).
3. **Вето правил после LLM — внутри функции, одним местом в `POLICY`** (существующие функции, не новые):
   `policies._has_refusal_or_hedge` («не отменяйте», «не надо») и `is_context_negative` гасят «да» LLM;
   `explicit_operator_requested` при висящем вопросе — сужение: LLM `no` → перевода нет. Данные МИС (врач в реплике у
   вторичного оффера) — тоже сужение здесь.
4. **Сбой LLM (`fallback`)** — нынешние правила обработчика (решение Q1) + предел переспросов (`_expects.asks`).

**Таблица политик** `pending_answer.POLICY` — одна, в коде:

| Тип | Полярность | Исходы | Ограничение |
|---|---|---|---|
| operator_offer | да/нет | yes → перевод | yes от правил ИЛИ LLM; yes+хвост — перевод; отказ («не надо оператора») — не перевод |
| catalog_confirm | да/нет | yes → сущность; no → уточнить; 2-й no → оператор | yes+хвост — не «да», хвост в NLU; во «2-е нет» — только настоящие `no` (не `none`/сбой, не no+хвост с услугой) |
| appointment_abort | да/нет | **только yes** стирает собранное | вето `_has_refusal_or_hedge`; pause/new_topic/none — собранное цело, снят флаг |
| appointment_action | выбор | cancel → оператор; reschedule → дальше | глагол отмены не глушится «нет»/«пауза»; распознанная отмена → оператор при любом состоянии LLM |
| secondary_offer, show_all | да/нет | yes → ответ на вопрос | yes+хвост — не «да», хвост в NLU (ложное «да» = чужая цена) |
| compound_price | выбор | pick → цена этой услуги | только явный pick; yes+хвост — хвост в NLU |
| anesthesia | выбор | pick → памятка | только явный pick; сомнение/сбой → обе памятки или переспрос (решение 07.10) |
| booking_service, appointment_branch | выбор | pick → слот записи; «любой филиал» → оператору как есть (18.10) | пункт — только из показанных; слот из `pick`, `quick_fill` — только прочие слоты; new_topic/pause → вопрос abort ИЛИ NLU (precheck читает Answer) |

Границы функции (не второй путь — записано явно): выше неё срочное (`detect_urgent`), явный запрос оператора **без**
висящего вопроса, охрана города, `orchestrator.early_guards` (метки безопасности); вне её — дата, время, ФИО (не
`_expects`). Кнопка снимает вопрос — функция не зовётся.

**Бюджет хода** (2 решения LLM): функция — первым вызовом; исход закрыл ход — дальше ничего; `no/new_topic/none` или
хвост → обычный путь; такое решение функции лимит не тратит (Q5).

**Что удаляется в коммите-переключении** (под выключателем — оба пути до карточки, затем снятие):
вызовы правил разбора из 11 обработчиков и решателей §1 (остаются только как `fallback` внутри функции);
`_SECONDARY_SOFT_YES_RE`, `_COMPOUND_PRICE_SOFT_YES_RE` (храповик −2); `reply_kind_for`, `branch_reply`,
`pending_reply_types`, тень `pending_reply`; третий решатель `appointment_action` в `_extract_pending_response`.

**CONFIRM** (решение Q2, уточнено консилиумом): мигрировать не нужно. Убрать блок CONFIRM в `run_appointment_precheck`,
ветку `appointment_confirm_pending` в `mess_types.SessionState.__post_init__`, тип `appointment_confirm` в `expects`,
`appointment_confirmation_transition`, `_is_unambiguous_yes`, `_CONFIRM_YES_WORDS`. Значение `AppointmentPhase.CONFIRM`
оставить на релиз недостижимым (10 кортежей `(COLLECTING, CONFIRM)` в `orchestrator`/`router`); `reject_appointment_
confirmation` — оставить (им пользуется abort). Тесты на фазе — перенести на abort, не удалить.

# DESIGN-2026-10-28-POSITION-QUALIFIERS — уточнения позиции: один механизм на условие, материал, метод и сопутствующую услугу

Решения владельца 27.10, пп. 4, 5, 7, 12 (`docs/OWNER_DECISIONS.md`; таблица консилиума — `~/Dev/handoffs/consilium/2026-10-27_decisions_table.md`,
ответы сессий «архитектура» и «Рефакторинг Next» — `2026-10-27_*_answers.md`). Принципы: п. 1 «дезинформация ценой хуже уточнения»,
п. 2 LLM-first (смысл решает LLM, код — механика), п. 3 честный ответ при сбое. Код — по этапам ниже, каждый под выключателем
`[MESSENGER_ROUTER] position_qualifiers` (умолчание off), с карточкой и встречным свипом.

## 1. Класс

В вопросе о цене у услуги бывают **уточнения** — слова пациента, которые меняют, какая строка прайса ответ:

| Вид (`kind`) | Что | Примеры | Где теряется сейчас |
|---|---|---|---|
| `payment` | кто и как платит | «по ОМС», «по полису», «по ДМС», «бесплатно», «по направлению» | разметка отрывает от названия, у списка суда нет — розничная цена (BUG-2026-10-26-LIST-CONDITION-CUT-BY-SPANS); во втором ходе без названия — цена услуги контекста (BUG-2026-10-27-OMS-FOLLOWUP-PRICED) |
| `condition` | прочие условия строки | «срочно», «на дому», «первичный», «детский» | то же; «на дому» — отдельные строки прайса |
| `material` | материал, орган, объект | «кала», «мочи», «из зева», «вен» | пул по буквам: «посев кала» → общие посевы (g0372), «УЗДГ вен» (g0651), «посев мочи с чувствительностью» → другой материал (g0811) |
| `method` | метод, форма результата | «количественным методом», «ПЦР», «суммарные» | выбор ставит «нашёл варианты» мимо метода: «ВПЧ количественным» (g0604), «ПЦР на аскаридоз» → антитела (g0847), «антитела к аннексину суммарные» → IgG / IgM (g0388) |
| `addon` | сопутствующая услуга | «под наркозом», «с седацией» | «наркозом» ≠ «наркоз» буквами (g0358); решение 20.10 `4cec16e`: наркоз — **вторая позиция**, нет строки — «стоимость наркоза уточнит оператор» |

Уточнение теряется в четырёх местах: **разметка** (`turn_spans` не заполняет `ParsedPhrase.beside` — суд условия у позиции списка его
не видит), **контекст** (короткий вопрос после цены берёт показанные строки раньше любой проверки — `_rows_shown_before`), **пул**
(кандидаты собираются по буквам фразы, уточнение-словоформа выпадает), **выбор** (заголовок «нашёл варианты» пишется без отметки, есть ли
уточнение в строке).

Почему не правилом: попытка 26.10 (`list_condition_beside`, ветка `claude/2026-10-26-list-condition-check`) раздавала позициям слова вне
фраз кодом по соседству — разговорные слова («первый раз», «завтра утром») ушли на суд: 8 потерь верных цен на эталоне, 0 улучшений
вне свипа. Уточнение к позиции относит тот, кто делит реплику на позиции, — LLM разметки, тем же вызовом.

## 2. Схема разметки (этап 2)

Ответ `turn_spans` получает второе поле (промпт `turn_spans_qualifiers`, две локации; старый промпт под off не меняется):

```json
{"phrases": [[1, 1], [5, 5]],
 "qualifiers": [{"of": 1, "words": [2, 3], "kind": "payment"}]}
```

- `of` — номер группы в `phrases` (с 1), к которой относится уточнение; `0` — ни к одной услуге (условие на весь вопрос или вопрос без
  названия: «а сколько стоит по омс?»).
- `words` — номера слов уточнения (как у групп); `kind` — закрытый перечень из пяти видов (§1).
- **Границы групп — как сейчас** (правило 3 промпта: уточнение входит в название группы). Уточнение отмечается и внутри группы: так код
  знает его вид, а пул и выбор по-прежнему ищут по фразе с уточнением. Вынести уточнения из групп — этап 3 вместе с пулом, иначе «мазок»
  без «из зева» уйдёт в поиск раньше, чем пул научится собирать кандидатов по уточнениям.
- **Не уточнение**: время, подготовка, вежливость, повтор («завтра утром», «натощак», «первый раз», «срочно ли нужно») — правило промпта.
- Битое уточнение (номер вне списка, `of` вне групп, вид вне перечня) отбрасывается, группы остаются; сбой всей разметки — как сейчас.
- Данные: `ParsedPhrase.qualifiers` (вид, слова, внутри / вне группы) и `beside` — слова её уточнений **вне** группы (раньше `beside`
  заполнял только генератор окон по соседству); `PhraseParse.loose` — уточнения с `of = 0`.
- Решений LLM — те же (поле в существующем вызове). Ответ длиннее на пару токенов на уточнение: `num_predict` разметки — с запасом на
  уточнения; замер времени разметки — в карточке (ёмкость, п. 2 решений 27.10).

## 3. Читатели

**Этап 2 — поле и страховка оплаты** (BUG-2026-10-26-LIST-CONDITION-CUT-BY-SPANS, BUG-2026-10-27-OMS-FOLLOWUP-PRICED):
- **оплата у позиции** → у позиции нет розничной цены, без суда LLM. Прайс МИС — розничный (`priceByRegion`; срез 08.10: 0 из 3 671 строк
  про ОМС, ДМС, полис, «бесплатно»), вопрос об оплате иным способом он не отвечает по определению. Одна услуга — исход П2 «условия нет»
  (`qualifier_absent` → «не нашёл», тот же текст, что у суда условия сейчас); позиция списка — «Не распознал: <слова пациента>», соседние
  позиции — своими ценами;
- **оплата без позиции** (`of = 0`) → на этом ходе цен нет: одна услуга и короткий вопрос после цены («а по омс?») — тот же исход П2;
  список — названия позиций без цен и оффер (как `basket_fail_unpriced`);
- **прочие виды вне группы** → `beside` → прежний гард и суд условия корзины (`phrase_price_items`), как было у генератора окон до 24.10;
  внутри группы — фраза слабая, её ведёт прежний путь (гард П2 по фразе).
- Гард П2 по буквам (`query_has_unsatisfiable_qualifier`, `_qualifier_outside_strong_phrase`) остаётся страховкой на случай, когда LLM
  уточнение не отметила; снимать его — отдельным шагом LLM-first со свипом П2 (урок RISK-2026-10-25-STRONG-PHRASE-NO-GUARD).

**Этап 3 — пул по названию и уточнениям** (g0372, g0358, g0651, g0811): группы — без уточнений, уточнения — отдельно; кандидаты — по
названию **и** уточнениям, словоформы — по основам (`russian_nlu.tokens_share_stem`, `synonym_wordforms`; образец — `same_name_rows`
невлитой ветки `doctors_by_parse`, `39a0dd9e`; не стоп-лист); второй круг по
`search_terms` (есть) не теряет уточнение; `addon` — вторая позиция корзины («ФГДС под наркозом» → ФГДС + наркоз; строки наркоза нет —
цена ФГДС и «стоимость наркоза уточнит оператор»). Метрика — Recall@pool (`price_pool`) на подмножестве «уточнение в вопросе»; класс
«уточнение теряется до выбора» — в общие наблюдения журнала.

**Материал — по данным МИС (уточнено 28.10, разбор g0372).** У услуги МИС есть поле `biomatNames` (1 540 из 1 584 услуг справочника):
у «Посева на микрофлору (идентификация агента и чувствительность к а\б)» — 37 материалов, «кала» среди них нет; у «Дисбактериоза кишечника
(…)» — «кал, кал (Ор)»; материал «кал» — у 41 услуги («Посев на патогенные энтеробактерии», «УПЭ — исследование кала на условно-патогенные
энтеробактерии», «Кал на стафилококк…», «Посев на грибы рода Candida…»). Отсюда механика без списков в коде:
- уточнение вида `material` сверяется с `biomatNames` строки по основам слов («кала» ~ «кал», «мочи» ~ «моча») — **данные решают, есть ли
  материал в строке**; у услуг без материала (исследования, приёмы: «УЗДГ вен») — по словам названия строки;
- пул позиции с материалом = кандидаты по названию, у которых материал есть, **плюс** услуги с этим материалом (по `biomatNames`), ближайшие
  по названию к фразе (топ-N); строки по названию без материала («Посев на микрофлору» для «посева кала») в пул не идут — общий посев не
  ответ на посев кала (п. 7 решений 27.10);
- какая из строк с материалом — та услуга, решает выбор LLM по смыслу («посев кала на микрофлору» → «Дисбактериоз кишечника» или
  «Посев на патогенные энтеробактерии» — варианты списком, принцип 1); приравнивать кодом нельзя (синонимы — клиники).

Нынешние ответы прода на случаях этапа 3 (`s19all_*`): g0372 — общий посев 1 120 / 1 200 руб. (чужая услуга); g0358 — ФГДС 5 100 руб. без
слова о наркозе (строки наркоза для ФГДС в прайсе нет: только «Диагностический профиль перед … ФГДС под общим наркозом» — анализы);
g0651 — в dev «УЗИ слюнных желез … (УЗДГ)» 1 400 руб. (обзор голого названия, `bare_name_overview`; «вен» потеряно), в кнопках — дуплекс
вен и «Не распознал: УЗДГ вен»; g0847 «посев мочи с чувствительностью» — «точно в таком виде нет, есть посев мочи с идентификацией» (верно:
строки с чувствительностью нет).

**Этап 4 — заголовок по отметкам** (g0604, g0388, g0811, g0847): схема выбора строки получает по каждому уточнению отметку `in_row: yes | no`;
заголовок («нашёл» / «точно в таком виде нет, есть: …») пишет код по отметкам, слова кодом не сверяются; ярлык `partly`
(`test_assist_answer`) — по тем же отметкам.

**Этап 5 — кнопки цены** `button_answer_topic = on` (карточка С5 25.10 и 27.10: +3 чужие цены — g0388, g0811, g0847, класс этапов 3–4).

## 4. Без LLM, лимит решений, безопасность

- Разметка не ответила — как сейчас: без LLM — только дословное название или код, без цены внутри вопроса (решение 27.10).
- Этапы 2–3 — 0 новых решений хода; этап 4 — поле в существующем выборе строки. Отказ лимита решений — как сейчас (уточнение).
- Уточнение — данные хода, не текст ответа: в ответ идут только слова пациента, приведённые в его порядке.

## 5. Замер каждого этапа

- Контроль off: повтор из кэша против `s19all_*` (кнопки, test, dev) — 0 отличий.
- Карточка on (`cached`, живая LLM только на промахах кэша — новый промпт разметки, ≤ 2 потоков): против `s19all_*` — цена при условии
  оплаты → 0; чужая цена не растёт; верные цены соседних позиций и одной услуги без уточнения не теряются; статусы разметки (`invalid`,
  `none_fit`) и время разметки p50 / p95; решений LLM на ход.
- Встречные свипы: `bench/sets/list_condition_2026-10-26.jsonl` (28 своих списков с условием, разговорными словами и без), свип П2
  `p2_strong_phrase_sweep` (205: «<услуга> по омс», «по полису», разговорные, контроль) — on не хуже off поимённо.

## 6. Вопросы владельцу

1. **ДМС — это оплата?** Сейчас суд условия иногда отдаёт розничную цену на «по ДМС» (свип 26.10: оба «по ДМС» — с ценой). По этому дизайну
   ДМС — вид `payment`, у позиции нет розничной цены (честнее: цену по ДМС бот не знает). Нужен ли пациенту с ДМС розничный ориентир
   («по ДМС — уточнит оператор; без полиса — 530 руб.»)?
2. Текст при оплате: сейчас «не нашёл» (исход суда условия). Предложение на потом — «Цен по ОМС у меня нет: в прайсе — платные услуги.
   Перевести на оператора?» (факт данных, не догадка) — по слову владельца, отдельной правкой.

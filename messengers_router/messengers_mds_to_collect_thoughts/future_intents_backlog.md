# Future Intents Backlog

Этот список фиксирует интенты, которые пока не вводим в канонический `Label`, но планируем в следующих этапах.

Текущее поведение (Этап 1):

- такие запросы маршрутизируются как `OTHER` + `handoff=true`;
- в `classifier` ставится флаг `doc_request_handoff` для документных кейсов.

## 1) CERTIFICATE / DOC_REQUESTS

Примеры запросов:

- справка для налогового вычета
- копия договора с печатью
- копия амбулаторной карты
- протокол приема

План:

- выделить отдельный label после согласования бизнес-процесса;
- добавить отдельные слоты (`doc_type`, `period`, `patient_identity_mode`);
- завести безопасный контур авторизации/проверки личности.

## 2) RESULTS_DOCS (расширенный TEST_RESULT)

Примеры:

- результат не пришел на почту
- выгрузка результата на почту/сайт
- PDF бланк анализа

План:

- оставить текущий `TEST_RESULT` как базовый;
- расширить до отдельного документного потока после подключения API и auth.

## 3) INSURANCE_DMS_OMS

Примеры:

- консультация по ДМС
- проверка покрытия страховой программы

План:

- отдельный label и сервис интеграции с данными страховых программ;
- правила handoff при отсутствии точных данных.

## 4) B2B / CORPORATE

Примеры:

- заключение договора на медосмотры
- коммерческое предложение

План:

- отдельный non-patient поток;
- отдельные шаблоны и маршрутизация на менеджеров.

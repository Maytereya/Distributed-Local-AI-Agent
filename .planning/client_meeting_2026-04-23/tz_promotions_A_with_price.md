# ТЗ: Акции и новости в чат-боте

**Версия:** А (после доработки API на стороне Nayka)
**Срок:** 8 рабочих дней (≈1.5 недели) после готовности API
**Стоимость:** 240 000 ₽
**Объём:** ~60 человеко-часов

---

## 1. О функции

Бот должен научиться:
- замечать актуальные акции, когда пациент спрашивает что-то связанное (анализ, приём врача, услугу);
- по прямому вопросу «какие у вас сейчас скидки/акции» — выдавать список релевантных предложений;
- передавать диалог оператору, когда условия акции требуют живого уточнения.

Источник данных — метод API клиники `/api/v1/site/promotions`.

---

## 2. Как это будет выглядеть в чате

**Сценарий 1 — пациент спрашивает анализ, на который есть акция:**

> **Пациент:** Сколько стоит общий анализ крови?
> **Бот:** Общий анализ крови (полный) — 520 руб. Сейчас на эту услугу действует акция: «Главный тест вашего здоровья» — скидка 50% до 30 апреля 2026 г. Цена со скидкой: 260 руб.

**Сценарий 2 — прямой вопрос про акции:**

> **Пациент:** Какие у вас сейчас акции?
> **Бот:** Сейчас в клинике действуют такие акции:
> 1. ПЦР-тест на COVID-19 — скидка 70% (до 31.12.2026)
> 2. Общий анализ крови — скидка 50% (до 30.04.2026)
> 3. Витамин D — 10 и 25 числа каждого месяца
> 4. Скидка 30% на приём гинеколога (до 30.04.2026)
> 5. Ещё 6 акций — показать?

**Сценарий 3 — акция требует уточнения у оператора:**

> **Пациент:** Хочу записаться к гинекологу.
> **Бот:** До 30 апреля действует акция «При записи на приём к врачу акушеру-гинекологу — два важных исследования бесплатно». Условия зависят от конкретного врача — соединяю с оператором.

## 3. Часть 1: Что должна сделать команда Nayka (Виктор)

Эта часть **обязательна** для запуска функции по варианту А. Мы не сможем дать корректный результат, пока поля не заполняются.

### 3.1. Что сейчас не так

Мы протестировали реальный API на 20 текущих акциях. **Все структурированные поля пустые**:

| Поле API | Должно содержать | Сейчас |
|---|---|---|
| `id` | уникальный идентификатор | null во всех 20 акциях |
| `startDate` | дата начала действия | null во всех 20 акциях |
| `endDate` | дата окончания действия | null во всех 20 акциях |
| `services` | id услуг, на которые распространяется акция | пусто во всех 20 акциях |
| `workers` | id врачей, к которым привязана акция | пусто во всех 20 акциях |
| `regions` | id филиалов, где действует акция | пусто во всех 20 акциях |
| `isAnalysis` | флаг «акция на анализ» | null во всех 20 акциях |
| `isDoctorService` | флаг «акция на приём врача» | null во всех 20 акциях |

### 3.2. Что нужно сделать Виктору

#### Задача 1. Технические поля акции

Для каждой акции в БД (и для всех новых, создаваемых через CRM) — заполнить:

- **`id`** — стабильный уникальный идентификатор. Любой формат (число, UUID, строка), главное — не меняется при редактировании.
- **`startDate`** — дата начала, формат `YYYY-MM-DD`. Если бессрочно — оставить `null`, но это нужно зафиксировать как договорённость.
- **`endDate`** — дата окончания, формат `YYYY-MM-DD`. Для бессрочных — `null`.
- **`isAnalysis`** — `true`, если акция касается лабораторных анализов.
- **`isDoctorService`** — `true`, если акция касается приёма врача.

#### Задача 2. Привязка к услугам

Поле **`services`** должно содержать массив идентификаторов услуг, на которые распространяется акция. Можно использовать те же `serviceHomecode`, что используются в эндпоинте прайс-листа (например, для «ПЦР-тест на COVID-19» это код 75, для «Общий анализ крови (полный)» — код 501).

**Пример (правильно):**
```
{
  "title": "Скидка 70% на ПЦР-тест на COVID-19",
  "services": ["75"],
  ...
}
```

**Пример (неправильно — как сейчас):**
```
{
  "title": "Скидка 70% на ПЦР-тест на COVID-19",
  "services": [],
  ...
}
```

#### Задача 3. Привязка к врачам

Поле **`workers`** должно содержать массив `doctorId` тех врачей, к которым относится акция. Если акция «общая по специальности» (например, скидка 30% на любого гинеколога) — заполнить всех гинекологов клиники.

#### Задача 4. Привязка к филиалам

Поле **`regions`** должно содержать массив id филиалов клиники, где действует акция. Если действует во всех — заполнить всеми id, **не оставлять пустым**.

#### Задача 5. Изменения в CRM/админке

Когда администраторы клиники создают новую акцию через интерфейс CRM — все поля выше должны быть **обязательны к заполнению** (или с разумными дефолтами). Иначе ситуация повторится: акции добавляются, поля остаются пустыми, бот их не видит.

### 3.3. Срок и приёмка

- Виктор подтверждает срок реализации задач 1–5.
- На стороне Nayka все 20 текущих акций должны быть актуализированы (заполнены поля).
- Перед стартом наших работ — мы делаем контрольный запрос к `/promotions` и подтверждаем, что:
  - все 20 акций имеют непустые `id`, `startDate`, `endDate`;
  - не менее 80% акций имеют непустые `services`;
  - акции, привязанные к конкретным врачам, имеют непустые `workers`;
  - все акции имеют непустые `regions`.

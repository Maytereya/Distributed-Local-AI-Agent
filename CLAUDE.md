# Контекст проекта для Claude Code

Медицинский чат-бот клиники «Наука» (Самара). Отвечает пациентам о ценах,
адресах, подготовке к анализам, записи к врачу; при неуверенности переводит на
оператора.

**Этот файл держит то, что НЕ меняется** — правила, карту и ловушки. Текущее
состояние живёт в хэндоффе (см. карту ниже) и устаревает быстрее всего.

## Направление проекта — LLM-first (решение владельца, 27.10)

- **Цель — бот, который понимает смысл (LLM-first).** Постепенно заменяем правила, регулярки и буквенные
  совпадения, которые дают неверные ответы, на решение LLM; правила остаются только там, где они сужают
  кандидатов для LLM, разбирают данные МИС или структурный ответ (цифра, дата, да/нет) — или по замеру
  верны и дёшевы.
- **Никаких разовых патчей под одну фразу.** Фикс чинит класс бага и делает шаг к LLM-структуре; «верное
  решение» для одного случая, не связанное с классом, — не делаем. Перед фиксом — архитектурный взгляд:
  помогает ли он перейти от букв к смыслу (`docs/ARCHITECTURE_PRINCIPLES.md`).
- **Снятие правил — по замеру, не разом:** правило, которое перехватывает раньше LLM, переводим на LLM по
  одному, с карточкой против базы; удаляем код, когда LLM-путь доказал себя (неделя on), храповик правил
  `tests/test_rules_ratchet.py` только опускается.

## Главная сессия — штурман; наследник при ~950k контекста (решение владельца 29.10)

- **Главная сессия держит цель и архитектуру, не рутину багов.** Перед фиксом — где в цепочке решается класс (правило → регэксп →
  NLU → перехват → LLM) и сколько слоёв его перехватывают; чинить слой-источник. Правка, которая чинит один случай и ломает соседний, —
  сигнал переплетения слоёв: разобрать цепочку и снять лишний слой, а не добавлять ещё один.
- **~950k токенов контекста** (или предупреждение о сжатии) — спросить владельца: «Передать наследнику?». «Да» — хэндофф по шаблону
  `~/Dev/handoffs/SUCCESSOR_TEMPLATE.md` (раздел «зачем» переписать, разрешения — дословно), запуск наследника, дочерним сессиям —
  отчитываться наследнику. «Нет» — сессия вспомогательная, хэндофф не пишет.

## Правила работы

- **Атомарные коммиты.** Один фикс — один коммит.
- **Гейт: `ruff check messengers_router tests` + полный `pytest`.** Область ruff —
  как в CI: `ruff check .` даёт ~50 старых ошибок в чужом коде (FreeTalk, tools),
  их попутно не чинить. Коммит только по ЗЕЛЁНОМУ. Читать
  фактический exit-код и сводку pytest: «completed» у фоновой обёртки **не равно**
  зелёному прогону, и `$?` после пайпа относится к последней команде, не к ruff.
- **Полный pytest — параллельно:** `./venv/bin/python -m pytest -q -p no:cacheprovider -n auto`
  (pytest-xdist из `requirements-ci.txt`): ~3,5 мин на 10 ядрах Mac против ~18 мин в один
  поток, результаты поимённо те же (20.10). Тест не делит с соседом ни файл, ни папку: всё,
  что пишет, — в `tmp_path`; журналы хода и синонимов conftest уже уводит во временный каталог.
  Падение только под `-n` — это утечка общего состояния, чинить изоляцией, не исключением теста.
- **Гейт герметичен: сеть в тестах закрыта** (`tests/conftest.py`, «Изоляция
  сети»). До 29.09 тесты через `config.ini` ходили в прод-LLM и МИС: при плохой
  сети прогон шёл больше часа и грузил LLM пациентов.
  Тест, которому живые системы нужны по смыслу, — `@pytest.mark.live`: в гейт не
  входит, запуск вручную `pytest -m live`. Попытки выйти в сеть печатаются в
  сводке прогона — это список ещё не изолированных тестов, а не ошибка.
- **К каждому гарду — встречный свип по живым данным.** Целевой тест гарда
  показывает, что тот запрещает нужное, и молчит о том, что он глушит лишнее.
  15.09 свип поймал подмену онкомаркера анализом на кальций (182 названия из
  1200) при полностью зелёных целевых тестах.
- **Промпты в ДВУХ локациях:** `messengers_router/prompts/*` и
  `app_data/prompts/mr_*`. Менять обе, иначе прод возьмёт старую версию.
- **Баги — в `docs/messengers_router_bug_log.md`:** симптом · корень · фикс ·
  **инвариант класса** · покрытие. Тест на КЛАСС, не на инстанс.
- **NLU чинить LLM-first**, не стоп-листами под одну фразу.
- **Репозиторий ПУБЛИЧНЫЙ.** Не коммитить ПДн, учётные данные, прод-топологию.
- Рассуждать можно по-английски, **выводы и план — по-русски**.

## Принципы предметной области

**Архитектурная «конституция» — `docs/ARCHITECTURE_PRINCIPLES.md` (5 пунктов, 08.10).** Каждый фикс
ссылается на пункт; нарушение — только явным решением владельца.

- **Дезинформация ценой строго хуже уточнения.** При неоднозначности показываем
  список вариантов, а не единственную (возможно чужую) цену. Решение владельца
  2026-07-22, действует для буквенных семейств, синонимов и вариантов услуги.
- **Синонимы услуг придумывает КЛИНИКА, не мы.** «Мазок» и «посев» пациенты
  используют как одно, но это 290-510 руб. против 1120. Приравнивать —
  медицинское суждение. Наше дело — показать, что и сколько раз писали пациенты.
- **Данные из МИС, не списки в коде.** Словари синонимов и биоматериалов
  приходят из справочника; в коде — механика, а не содержимое.

## Перед важным решением — где искать ответ

Контекст между сессиями теряется; прежде чем решать самому или спрашивать владельца — найти, не решалось ли это уже.
От дешёвого к дорогому:

1. **Решения владельца** `docs/OWNER_DECISIONS.md` (только дописывать, с датой) и **журнал багов** `docs/messengers_router_bug_log.md` — «почему так сделано», решения владельца по шагам рефакторинга
   (записи `STEP-…`, `BUG-…`, `INC-…`, `DEBT-…`; `grep -n` по ID и ключевым словам). Читать запись ДО вариантов фикса.
2. **`docs/ARCHITECTURE_PRINCIPLES.md`** (5 принципов) и тесты на класс (`tests/test_*_class.py`, эталоны `tests/golden/`) —
   какое поведение задумано; xfail strict — известный, ещё не закрытый дефект.
3. **Хэндоффы:** локально — `~/Dev/handoffs/` (свежий `*_kickoff.md`, `2026-10-07_MASTER_refactor.md` §7.1 «Решения»,
   `*_findings.md`, `*_design.md`, `dla/`); в репо — `docs/HANDOFF_*.md`.
4. **Локально — память сессий:** claude-mem (`mcp__plugin_claude-mem_mcp-search__search`, `obs_type="decision"` →
   `get_observations`) и память проекта Claude Code; затем консилиум прошлых сессий — только для архитектурных и
   необратимых решений (дорого: сессия перечитывает весь свой контекст).

**Облачная сессия** видит только репозиторий: нет `~/Dev/handoffs`, claude-mem, памяти проекта, `~/Dev/dla-private`
(стенд, разметка), `config.ini`, срезов `apidata`, VPN и прода; отвечать другим сессиям она не может.
- Источники — только п. 1–2 и `docs/HANDOFF_*.md`, `docs/DESIGN_*.md`. Чего в них нет — не додумывать: выбрать вариант с меньшим риском
  (под выключателем, по умолчанию «как было»), а вопрос владельцу записать в свой хэндофф
  `docs/HANDOFF_<дата>_cloud_<тема>.md` (раздел «Решения на проверку владельцем»).
- Гейт в облаке падает на ~230 тестах окружения (врачи, прайс, живой каталог): сравнивать множество упавших ДО и ПОСЛЕ
  своих коммитов поимённо — новых быть не должно; полный гейт — потом на Mac.
- Пушить только свою ветку; `release`, `backup/*`, сервер, деплой — нельзя.

## Ловушки

Каждая стоила времени. Список дороже любой документации по архитектуре.

**Переключатель LLM в Gradio меняет прод в обход гита и конфига.** Пишет в
`/app_data/settings/main_model.txt`, и этот файл ПОБЕЖДАЕТ `config.ini`. При
любых странностях с LLM смотреть туда первым.

**`app_data/settings/` лежит в гите** — включая `main_model.txt`. Обычный
`git reset --hard` способен молча переключить модель прода.

**Ошибка прода читается из HTTP-ответа, SSH не нужен:** запрос с `"debug": True`
кладёт текст исключения в `state_update.debug.route_error` (`endpoint.py`).
15.09 это дало корень за минуты вместо часов.

**`--remove-orphans` опасен.** Основной compose и `docker-compose.ollama.yml` —
разные проекты; флаг удалит контейнеры соседнего.

**Ollama: `--gpus all` не включает раскладку модели по картам.** Нужен
`OLLAMA_SCHED_SPREAD=1`, иначе потолок — одна карта (24 ГБ при 94 ГиБ суммарно).

**Карты — 4 × RTX 4090 по 24 ГБ = 94 ГиБ**, не 256. Прикидки по выбору модели,
сделанные до 15.09, недействительны.

**После самарской полуночи словарь синонимов МИС молча становится ПУСТЫМ.**
Срез датирован по Самаре (UTC+4). В 00:00 по Самаре файла «на сегодня» ещё нет,
`load_service_info` уходит скачивать его у клиники, а `_vocabularies()` по своей
конструкции гасит любой сбой и возвращает пустой словарь — без исключения, без
ошибки в выводе. Бот в этот момент работает без 872 синонимов. 17.09 это
превратило свип «74% промахов гарда» в «82% не распознано» и выглядело как
успешная починка. С 03.10 загрузчики берут последний непустой срез
(`agent_logic_2/nayka_api/snapshots.py`), но ценовой путь (`_biomaterial._vocabularies`)
до 08.10 смотрел только файл «на сегодня» и ночью всё равно отдавал пустой словарь (DATA-1:
65% из 214 синонимов без цены, 5% — чужая). С 08.10 и он берёт последний непустой срез;
пустым словарь станет, только если на диске нет ни одного среза. Любой замер на живых
данных всё равно начинать с печати размера словаря;
`scripts/audit_cart_misses.py` это делает и умеет прикрепляться к последнему
существующему срезу. Гейт от этого защищён целиком: синонимы в тестах
герметичны (`_hermetic_mis_synonyms`), а служебный справочник и прайс
прикреплены к последним существующим срезам (`_pin_latest_mis_snapshots`,
30.09 — после изоляции сети утром без среза «на сегодня» падал сбор тестов).

**Тест загрузчика без изоляции удаляет настоящие срезы.** Очистка старых срезов
(`api_price.cleanup_old`, `api_service_info._cleanup_old`) работает по папкам модулей,
а не по пути, который тест подменил. 03.10 прогон тестов на коде до фикса удалил
локальные прайс и `serviceInfoAll`, и гейт упал на пустом каталоге; `serviceInfoAll`
(45 МБ) МИС в тот вечер отдавала с обрывом. В тестах загрузчиков подменять пути,
папки И очистку (`tests/test_snapshot_files.py::_isolated`).

**Без локального среза врачей гейт берёт выдержку из репо.** `doctors_*.jsonl` в
`agent_logic_2/nayka_api/apidata/` не в git; до 18.10 без него 68 тестов врачей и записи
были красные. Теперь `tests/conftest.py` при пустой папке подставляет
`tests/fixtures/doctors_excerpt/` (41 врач, без описаний) — полный гейт зелёный и без
среза. Но поведение «как на проде» тесты видят только на полном срезе: если правка
касается врачей, гейт гонять с локальным срезом. Восстановить срез —
`api_nayka.get_cached_doctors_data()` при работающем VPN; `/site/doctors` (около 18 МБ)
через VPN бывает идёт часами и рвётся — повторить позже.

**Снимок прайса может отсутствовать, а API прайса — не отвечать.** 25.09
`priceByRegion/3` отдавал 400, и свежего файла не было. `pin_latest_service_info()`
в `scripts/audit_cart_misses.py` прикрепляет только `service_info`, прайс — нет.
Любой офлайн-замер начинать с прикрепления ОБОИХ срезов к последним
существующим файлам, иначе загрузка уйдёт в сеть и упадёт.

**`${PIPESTATUS[0]}` здесь пуст — оболочка zsh.** Нужен `$pipestatus[1]`, либо
писать вывод pytest в файл и брать `$?` без пайпа. Иначе «зелёный» гейт окажется
кодом возврата `tail`, а не pytest.

**Зелёный свип по живому прайсу бывает ложным.** Свипы берут выборку из
скачанного прайса (каждое N-е название). Прайс обновился — выборка сдвинулась.
29.09 «лучезапястного узи» выпало из выборки, и тест позеленел при живом
дефекте. Известный случай закреплять отдельным тестом, а не надеяться на свип.

**Локальный `config.ini` мог остаться со старым хостом прода** (хост сменился
02.09). Симптомы: ошибки Meilisearch в логе, PREPARE по процедурам локально не
находит правил, а на проде находит. 29.09 у max исправлено: каждый сервис
проверен на новом хосте, заменены только отвечающие (10 адресов из 12; VOSK
нет нигде). У второго разработчика config.ini свой — проверить так же. Перед
выводом «сломано локально» — сверить с продом.

**`[DEFAULT]` в `config.ini` перебивает `[MESSENGER_ROUTER]`.** Значения `[DEFAULT]` видны в каждом разделе, а
ключ ищется сначала в `[MESSENGER_ROUTER.<окружение>]` — и находится там из `[DEFAULT]` (имена без учёта регистра).
18.10 `debug_final_input = false` в `[MESSENGER_ROUTER]` не действовал из-за `DEBUG_FINAL_INPUT = True` в `[DEFAULT]`.
Проверять ключ по всему файлу (`grep -n -i "<ключ>" agent_logic_2/config.ini`), итог — `docker exec agent-api python -c
"from agent_logic_2 import config as c; print(c.<АТРИБУТ>)"`. И `config.ini` вшит в образ (`COPY . .`): правка конфига —
пересборка (`up -d --build`), не рестарт.

**Прод-движок NLU — `legacy_v2`, rule-path активен.** Промпт классификатора
forward-compat; реальное поведение задают правила. Когда LLM недоступна, бот
частично работает на правилах — это маскирует поломку.

**Конфигурация прода расходится с репозиторием молча.** Сервер не умеет пушить;
прод-правки переносить на машину разработчика. Сверять `git diff origin/release`
ЦЕЛИКОМ и через `| cat` — пейджер обрезает. 09.10 расхождение было уже в коде:
сборку поставили мимо схемы, с `docker-compose.override.yml` вне git — его compose
подхватывает при любом `up` (INC-2026-10-09-DEPLOY-BYPASS). До и после деплоя:
`git status` на сервере чистый; у `agent-api` метка
`com.docker.compose.project.config_files` — только `docker-compose.yml`; хэши
кода в контейнере равны коммиту.

## Проверка без VPN и без прода

```bash
# офлайн-репро цен на живом каталоге
./venv/bin/python -c "
from agent_logic_2.nayka_api import api_price
from messengers_router.services import _prices_helpers as H
ROWS=[r for r in api_price.load_price_by_region(H.SAMARA_PRICE_REGION_ID) if isinstance(r,dict)]
print(H.resolve_price_service_name_from_catalog('сколько стоит оак', rows=ROWS))"

# живость бота
./venv/bin/python scripts/check_bot_health.py --url http://ПРОД/api/messenger-generate-once
```

Справочники: `agent_logic_2/nayka_api/apidata/` — прайс региона, `service_info`
(синонимы, биоматериалы, подготовка), снимок филиалов.
